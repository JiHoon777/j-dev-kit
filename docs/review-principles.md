# 리뷰 원칙

`/task end`가 리뷰 에이전트와 판정 에이전트에 넣는다. 그대로 둔 지적과 사용자가 바로잡은 것에서 모은다.

- 기준 판(기준 브랜치, 그 판의 파일)을 구하지 못하면 조용히 넘어가지 말고 그렇다고 알린다 — 판정이 무엇에 대고 한 것인지 모르게 된다. 두 번 빠뜨렸다 (009, 010)
- 리뷰용 개발 서버는 끄지 않아도 된다 — 포트가 항목마다 달라 다른 항목과 부딪히지 않는다 (006)
- 테스트를 돌리는 스크립트는 테스트마다 시간 제한을 둔다 — 멈춘 테스트 하나가 검증이나 Stop 훅 전체를 취소시킨다. 두 번 빠뜨렸다 (009, 011)
- 승인된 계획·AC 가 명시적으로 정한 삭제나 범위는 그 자체로 버그로 보지 않는다 — 계획 때 사용자가 정한 것이다. 바꿔야 할 근거가 있으면 지적이 아니라 결정을 다시 볼지 묻는 것으로 올린다 (012)
