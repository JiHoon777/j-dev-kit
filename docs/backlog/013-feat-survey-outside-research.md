## Description

`/task create --survey`(`plugins/workflow/skills/task/references/create.md` 서베이 절)는 자료를 주지 않으면 저장소 안(오류 로그, 백로그, `gh issue list`, 사용 데이터)만 읽고, 바깥 자료는 사용자가 URL 을 줄 때만 본다. 후보는 한 세션이 한 번에 고르고, 후보 목록은 대화에만 남는다. 사용자는 "내부 자료만 보고 하는 게 별로고, URL 을 줄 순 있지만 기본적으로 알아서 검색해서 해야지"라고 했다.

바깥 실무자(Anthropic Research, Hamel Husain·Shreya Shankar 오류 분석, Teresa Torres, Claude Code `/dedupe`, GitHub Agentic Workflows, AI Goalie)를 조사한 결과, 공통으로 하는 것은 목표를 조사 질문으로 쪼개기, 바깥을 기본으로 찾기(1차 출처 우선), 각도별 병렬 수집, 자료별 메모 → 범주 → 세기 → 포화에서 멈추기, 다른 쪽이 거짓 양성 거르기, 조사 결과물을 남기기다. 서베이 모드가 이것을 하게 한다.

근거: `docs/backlog/references/2026-11-25-서베이-모드-전문가-조사.md`

가정:
- 바깥 조사는 기본으로 켠다. 빼는 것은 사용자가 그렇게 말할 때만이다(플래그 이름은 계획에서 정한다).
- 조사 질문과 각도는 보여 주기만 하고 승인을 기다리지 않는다.

이번에 빼는 것: 정기 실행, 서베이 결과로 `start`·세션 띄우기(008 에서 뺀 범위 그대로), 후보 수 상한, 점수 공식.

## Implementation Plan

### 1. 무엇을 하나

`create.md` 서베이 절을 "목표 쪼개기 → 안쪽·바깥 각도별 병렬 수집(메모 파일) → 메모·범주·세기·포화 → 판정 에이전트 거르기 → 보고서 → 고르기 → 쓰기"로 바꾸고, URL 없이 목표만 준 서베이의 동작 eval 을 더해 지금 판과 비교한다.

이번에 빼는 것(항목 그대로): 정기 실행, 서베이 결과로 `start`·세션 띄우기, 후보 수 상한, 점수 공식. SKILL.md `description`(트리거 문장)은 바꾸지 않는다(트리거 eval 을 다시 잴 일이 생기므로).

### 2. 도구와 단계

이 일은 "에이전트 절차 문서(스킬) 설계 + 그 효과 측정"이다. 실무자 방식: 근거 보고서(`docs/backlog/references/2026-11-25-서베이-모드-전문가-조사.md`)의 Anthropic 멀티 에이전트 리서치(위임 지시문 네 요소, 넓게→좁게, 1차 출처, 결과는 파일), Hamel 오류 분석(메모→범주→세기→포화), Torres(후보는 문제·필요, 크기·목표 영향, 공식 없음), `/dedupe`(별도 거짓 양성 거르기)를 절차에 옮긴다. 측정은 저장소 README 방식 그대로 `claude plugin eval`(판 두 개, `--runs 5`, `--judge-model sonnet`, 판정 규칙: 평균 차이 < 두 표준오차 합이면 "같음"). 설치할 것 없음.

확인한 eval 기능(claude-code-guide 답, 공개 문서 URL 없음 → 첫 실행의 결과 JSON 으로 다시 확인): 채점 `regex`(target `trace` 가능), `file_exists`(에이전트가 만든 파일, glob), `llm`(target `{source: file, path}`로 만든 파일 내용). `WebSearch`·`WebFetch`·`Write`는 `--allow-tools`가 필요하다.

### 계획에서 바뀐 것

- 보고서 내용 채점: eval 의 파일 `focus: {source: file, path}`는 glob 을 받지 않고 정해진 경로만 연다(claude 2.1.319 바이너리의 grader 코드에서 확인). 보고서 이름이 날짜·이름으로 바뀌므로, 보고서가 있는지는 `file_exists`(glob 지원) `.claude/.local/reports/*.md`로, 출처와 [직접]/[검색] 표시는 마지막 메시지의 후보 표(`report-sources`, llm)로 본다.
- `llm` 채점의 대상 키는 `target`이 아니라 `focus`다(`regex`만 `target`).
- 바깥을 빼는 플래그는 `--internal`. `SKILL.md`와 번역본의 `argument-hint`에만 더했고 `description`(트리거 문장)은 그대로다.

### skill-creator 방식에 맞춘 것 (사용자 지시, 2026-11-25)

사용자: "eval 작성은 skill creator 참고해서 하면 돼. 클로드코드의". 첫 실행을 시작한 뒤 받아, 돌던 실행을 멈추고 맞춘 뒤 두 판을 처음부터 다시 돌렸다.

- 맞춘 것(`skill-creator` `references/schemas.md` "Test cases"): `case.yaml`에 `expected_outcome`(성공 모습), 채점 파일 이름에 번호(`01-searched-outside.md` …), llm 채점에 `focus: trace`·`weight: 1`(채점자가 마지막 메시지만이 아니라 한 일도 본다. 보고서 내용을 기록의 Write 호출에서 볼 수 있게 됐다), 모든 채점에 `weight: 1`(점수 = 통과율).
- 맞춘 것(SKILL.md "Improving an existing skill"): 기준 판은 고치기 전 스킬의 사본(main 판)이다. 비교는 통과율·시간·비용의 평균 ± 표준편차와 차이, 그리고 분석(판을 가르지 못하는 채점, 들쭉날쭉한 채점)으로 한다.
- 그대로 둔 것: 실행은 `skill-creator`의 하위 에이전트 방식이 아니라 `claude plugin eval`로 한다(012 에서 정한 이유: 하위 에이전트 방식은 플러그인 로드·Skill 도구·`allowed_tools`를 시험하지 않는다. `plugins/workflow/evals/README.md`). `tags`는 이 저장소 다른 사례처럼 `case.yaml`에 둔다(스키마가 받는다). 사람이 볼 결과 화면은 `generate_review.py` 대신 eval 이 만드는 HTML 보고서를 쓴다.

### eval 실행

- 이 맥의 셸에서 `claude` CLI 가 로그인돼 있지 않아(`loggedIn: false`) eval 이 "Not logged in"으로 끝났다. 사용자가 `claude auth login`을 한 뒤 돌렸다.
- eval 실행은 `.claude/` 아래 쓰기를 막는다(dontAsk 모드, `--allow-tools 'Write(.claude/**)'`로도 안 풀림. 시험 사례로 `notes/` 경로는 쓰이고 `.claude/.local/`은 거부되는 것을 확인). 그래서 `02-report-written`은 파일이 아니라 그 경로로 Write 를 부른 기록을 본다. 실제 세션에서는 이 저장소가 이미 `.claude/.local/`에 쓰고 있다.
- 하위 에이전트의 도구 호출도 기록(trace)에 남는다(시험 사례로 확인).
- 사본: 지금 판은 `git archive main plugins/workflow`(af09fc4)에 새 사례를 넣은 것, 고친 판은 이 브랜치의 `plugins/workflow`. 둘 다 `dependencies`와 `hooks/`를 뺐다.
