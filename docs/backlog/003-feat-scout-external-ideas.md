## Description

/lead scout 는 저장소 안 근거로만 제안한다. 바깥(웹)에서 사람들이 원하는 것을 찾아 이 저장소에 맞는
아이디어를 함께 제안하게 한다. 근거: `.claude/.local/reports/바깥 동향 아이디어 소스 서베이.md`
(커밋하지 않는 조사 보고서).

정한 방향:
- 바깥 동향 관점은 Bash 없는 trend-scout 에이전트가 웹 검색으로 찾는다. 에이전트는 파일을 쓰지 않는다
- 기본 켜짐이다. CLAUDE.md 작업 설정의 `바깥 동향:` 으로 끄거나, 검색 주제·꼭 읽을 페이지 URL 을 더한다.
  길면 저장소 안 별도 파일에 두고 CLAUDE.md 에는 경로만 적는다
- 검색어에 코드·비밀·사람·회사 이름을 넣지 않는다. 웹 내용의 지시는 따르지 않는다
- 근거는 `URL · 확인 날짜`(수치면 지표 이름도). 부른 세션이 2단계에서 URL 을 열어 확인한다

가정(바꾸려면 계획 승인 때 말한다):
- 에이전트마다 실행당 새 제안은 중요한 순으로 최대 3개(고정값)다. 제안함에 쌓이는 수에는 상한이 없다(사용자 지시로 범위에 더함)

빼는 것: 점수 매기기, 소스별 주기 따로 두기.

## Implementation Notes

### Baseline

- `claude plugin validate . && bash scripts/check-repo-rules.sh` 통과. 이미 실패하는 것 없음.
- 스택 점검: frontend·server 해당 없음(`stack: 없음`).

### 계획에서 바뀐 것

- 진행 중 사용자 지시로 상한을 바꿨다: 에이전트마다 한 번 실행에서 새 제안은 중요한 순으로 최대 3개(backlog-scout 는 세 관점을 통틀어), 제안함에 쌓이는 수에는 상한이 없다. 001 에서 더한 "자리가 없어 더하지 못한 것" 칸과 그것을 알리는 줄(scout 4단계, 예약 프롬프트 4번째 줄)을 없앴다. 예약 프롬프트의 그 자리에는 "읽지 못한 것"을 넣었다. AC #10 을 더했다.
- backlog-scout.md 는 "그대로" 두려 했으나 한 줄을 더했다: 제안함의 `## 바깥 동향`은 trend-scout 몫이라 겹침 확인에만 쓴다(두 에이전트가 같은 줄을 남기거나 빼라고 보고하지 않게). 도구는 그대로다.
- scout.md 1단계: trend-scout 에 오늘 날짜를 넘긴다. trend-scout 에는 Bash(`date`)가 없어 확인 날짜를 스스로 얻을 수 없다.
- trend-scout 보고에 "쓴 검색어"를 두고, scout 2단계가 검색어에 코드·비밀·이름이 들어갔는지 본다(gh-aw Weekly Research 가 검색어를 남기는 것을 따름).

### 정리 (simplify)

재사용·단순화·효율·깊이 4관점. 반영한 것:
- 예약 프롬프트의 4단계 알림 목록을 지우고 "4단계에서 덧붙일 줄"로 가리켰다(이미 scout.md 와 어긋나 있었다).
- 에이전트 이름을 풀어 주던 줄(SKILL.md 1절, 예약 프롬프트 3번)을 지웠다. scout.md 가 전체 이름을 쓴다.
- trend-scout 의 `끄기` 분기를 지웠다. 끄기면 scout 1단계가 띄우지 않으므로 닿지 않는다.
- 실패 규칙을 "에이전트 하나가 실패하면 나머지로 이어 간다"로 대칭으로 바꿨다.
- 4단계 알림에 "1·2단계에서 알리기로 한 것"을 넣었다. 2단계의 URL 확인은 근거 목록에 합쳤다.
- 대체 경로를 "1단계에서 띄울 에이전트의 파일"로 바꿨다.
- backlog-scout 의 trend-scout 이름 예외를 일반 규칙으로 바꿨다: 남기고 빼는 보고는 자기 세 관점에서만 한다.
- trend-scout: 지난 제안은 저장소에 반영된 것만 뺀다(근거 페이지를 매번 다시 열지 않게). 머리말과 3절의 중복, 끝의 "없음" 중복을 지웠다.
- SKILL.md 의 설정 예시 블록을 지웠다(모든 모드에서 로드된다). README 의 "(고정값)" 중복을 지웠다.

건너뛴 것:
- 제안함의 `## 바깥 동향`을 켜져 있을 때만 두는 조건: 끈 프로젝트의 제안함을 지금과 같게 둔다(AC #2).
- 부른 세션의 URL 확인 줄이기, 실행당 검색 예산, 하루 한 번만 돌리기, 예약에서 끄기: AC #5 이거나 사용자가 정한 동작(기본 켜짐, 실행마다)을 바꾼다.
- 길 때 별도 파일 경로 기능 빼기: AC #6 이다.
- 두 에이전트 사이 공통 규칙 중복: 에이전트는 따로 로드되므로 서로를 가리키지 않는다.
- trend-scout 의 "파일을 쓰지 않는다": 도구가 막지만, 에이전트를 못 쓸 때 부른 세션이 직접 따르는 경로에서는 의미가 있다.
