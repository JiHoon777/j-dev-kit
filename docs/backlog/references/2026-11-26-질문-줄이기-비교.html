/task 에서 사람에게 묻는 곳: 지금과 바꾼 뒤

백로그 항목 하나를 create → start → end로 끝낼 때 사용자가 멈춰서 답해야 하는 곳을 비교했습니다. 기준은 하나입니다. 되돌릴 수 없는 일, 사람만 정할 수 있는 결정, 무엇을 할지 고르기만 묻고, 나머지는 정하고 적어 둔 뒤 끝에 한 번에 보여 준다. 계획 승인은 받지 않기로 하셨습니다.

지금 · 화면이 바뀌는 항목 하나 6~10번 DESIGN.md를 새로 만들면 최대 약 14번
→
바꾼 뒤 2~4번 AC 승인, 착수 전 질문(있을 때), 시안 고르기, 끝의 한 번
멈추고 답을 기다림 멈추지 않고 진행 (적어 두고 끝에 보여 줌) 없어짐
단계
지금
바꾼 뒤
create항목 쓰기
지금
  • 쓴 항목을 보여 주고 승인받음
  • 서베이면 후보 고르기
  • 고른 뒤 쓴 항목을 한 번 더 승인
  • 모호하면 brainstorming 질문superpowers 쪽은 질문을 하나씩 하고, 접근 방식도 승인받으려 함
바꾼 뒤
  • 항목의 AC 전문을 보여 주고 승인남김계획 승인이 없어지니 구현 전에 사람이 확인하는 유일한 계약
  • 서베이면 후보 고르기 한 번후보 표에 AC 초안을 넣어, 고르면 바로 씀
  • 고른 뒤 다시 승인
  • 모호할 때 질문은 한 번에 몰아서
start계획하고 구현
지금
  • 착수 전 질문 (스택 점검 + 계획 질문, 한 번에)
  • 시안: 몇 개 만들지 묻기 → 방향 표 확인 → 캔버스에서 고르기 → "됐다"
  • 계획 승인 (플랜 모드)
  • 구현 중: 새 색·글꼴, 범위 밖 일을 항목으로 만들지
  • simplify 돌릴지 묻기 → 고칠 것 고르기 (두 번)
  • TDD가 설정 파일 예외를 사람에게 물음이 저장소는 대부분 마크다운이라 걸림
바꾼 뒤
  • 첫 메시지에서 목표와 가장 작은 변경을 되짚고 바로 진행
  • 착수 전 질문은 있을 때만, 한 턴돌려 보면 답이 나오는 건 묻지 않고 돌려 봄. 질문이 있으면 아무것도 고치지 않고 기다림
  • 시안은 캔버스에서 고르기만취향개수는 기본 3개, 방향 표는 보여 주기만
  • 계획 승인
  • 계획과 스스로 정한 것은 항목 파일에 적고 기다리지 않음
  • simplify 질문 두 번 end의 code-review가 정리 지적까지 함
  • TDD 예외는 start가 미리 정해 넘김
end리뷰와 머지
지금
  • 🟡 지적마다 지금 / 나중 / 그대로, 🔁에는 "막기"까지
  • "나중"·"막기"로 만든 새 항목마다 승인
  • 머지 방식 고르기
바꾼 뒤
  • 🔴·🟡는 고치고 알림기록상 거의 늘 "지금 고침"이었음 (010 6/6, 012 4/4, 013 5/6)
  • "막기" 선택지 010~013 네 번 모두 안 고르심
  • 끝에 한 메시지로 몰아서: 스스로 정한 것 + 판단이 필요한 지적 + 머지남김결정마다 추천, 근거, 위험을 붙임

바꾼 뒤에도 늘 멈추는 곳

  • 머지, 푸시, 삭제처럼 되돌릴 수 없는 일
  • 커밋하지 않은 변경처럼 작업을 잃을 수 있는 상태
  • 프로젝트 밖이나 공유 설정을 바꾸는 일: 플러그인 설치, CLAUDE.md 줄 추가
  • 같은 기준이 세 번 고쳐도 실패할 때
  • 범위가 커질 때: AC 밖 동작, 새 의존성, 스키마·공개 API·삭제, 설정 변경
  • "이번엔 계획을 보자"고 하시면 그때는 계획을 보여 주고 기다림

그대로 두는 안전장치

질문을 줄여도 아래는 그대로 두니, 틀린 결정은 끝에서 잡힙니다.

  • 기준 브랜치의 검증 명령을 다시 돌리는 Stop 훅
  • 새 테스트가 고친 것을 증명하는지 보는 base-tests.sh
  • 구현한 세션이 아닌 판정 에이전트의 AC 판정
  • end의 리뷰와 판정 에이전트

계획 승인을 빼려면 같이 고칠 것

  • docs/review-principles.md:8: 지금은 "승인된 계획은 사용자가 정한 것"이라, 판정 에이전트가 Claude가 정한 가정까지 사용자 결정으로 보고 지적을 덮게 됩니다. AC와 사용자가 답한 것으로 좁힙니다.
  • start.md, task/SKILL.md, 항목 템플릿에 남은 "승인된 계획" 문구
  • 하위 세션 지시문의 "플랜 모드로 승인받는다"
  • superpowers 스킬(brainstorming, TDD, receiving-code-review, finishing)이 따로 묻지 않게 미리 정해 넘기기

진입 모드 스킬(/poteto-mode 같은 것)은 나중에

004에서 거의 같은 걸 만든 적이 있습니다. /until-done은 묻는 곳에서 스스로 정하고 되돌릴 수 없는 일만 묻는 모드였는데, 006에서 "쓰지 않는 것이 많다"며 지웠습니다.

그래서 이번에는 규칙을 따로 켜는 모드가 아니라 /task의 기본 동작으로 넣고(016), 써 본 뒤 /task 밖의 일에도 필요했는지 보고 진입 스킬을 정합니다(017).

근거: 플러그인 절차 파일 전수 확인, 끝난 항목 001~013 기록, pstack(cursor/plugins) poteto-mode·worker.md·플레이북. 에이전트 다섯 개(독립 분석 셋, 사실 검증, 반론 검토)로 다시 확인했습니다. 횟수는 절차를 따라 센 추정이고 실제 대화 기록에서 센 값은 아닙니다.
