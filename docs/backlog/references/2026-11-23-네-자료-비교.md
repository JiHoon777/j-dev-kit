## 1. 자료별 요점

### 1-1. 글 「한 달 PR 2,500개 머지했다는 개발자는 왜 PR을 다 리뷰하지 않을까?」

- 출처: https://maily.so/josh/posts/xyowyd21z28 (조쉬 뉴스레터. 1-2 영상을 Q&A 로 옮긴 글)
- 읽은 범위: 본문 전체(도입 ~ "1인 창업자를 위한 체크리스트" ~ 맺음, 끝의 광고 단락까지). 본문 이미지는 캡션만 읽었다. 캡션이 가리키는 X 글(10/17 "역피라미드", 10/19 pstack 새 스킬, 8/12 Dune)과 Claude Code 블로그 글은 원문을 열지 않았다.
- 요점(단락):
  - "에이전트 하나를 붙잡고 있던 사람 중계기": 탠은 에이전트와 Chrome 개발자 도구 사이에서 결과를 옮기던 자신이 병목이었다고 한다. 최신 모델도 지름길을 택하니, 스킬은 "쉬운 일이 옳은 일이 되게" 하는 것.
  - "첫 계단은 검증, 실수는 환경으로": 꼭 하나 있어야 할 스킬은 검증(에이전트에게 손과 눈). 검증 CLI 는 스킬의 결정적인 부분을 스크립트로 떼어 판단을 아끼려는 것. CLI 가 없을 때는 에이전트마다 검증 스크립트를 새로 짜고 버렸다. 실수를 볼 때마다 "린트 규칙으로 바꿀 수 있나, 코드베이스가 불가능하게 만들 수 있나"를 묻는다. 10/17 X 글의 역피라미드: 코드베이스 개선 > 린트·테스트 같은 자동 검사 > 주석·규칙 문서·스킬 같은 글 > 사람 리뷰, 노력의 대부분을 위쪽에.
  - "탠의 한 달 PR 2,500개는 어디서 오나": 바깥 루프(Slack·Linear·X)와 안쪽 루프(코딩 에이전트)를 이어, 버그 제보를 검증 스킬로 분류·재현(최신 코드에서도 재현되는지). 관련 이슈는 한 프로젝트로 묶는다. 이슈마다 에이전트를 하나씩 붙이면 실마리를 잃고 일을 중복한다.
  - "2,500개가 전부 기능은 아니다": 상당수는 정원 가꾸기. 나쁜 패턴을 찾는 정기 에이전트는 바로 고치지 않고 문서에 쌓고, 며칠마다 묶어 본다(버퍼).
  - "PR은 표본만 맛보고, 아침에 몰아 본다": 한 번 있었던 일은 괜찮다. 여러 에이전트가 같은 지름길을 퍼뜨리면 스킬·제약·린트·타입을 고친다. 풀 오토파일럿은 PR 마다 검증 에이전트가 앱을 퍼징하고 고쳐 머지. 일방향 문은 결국 검증을 얼마나 끌어낼 수 있느냐.
  - "남의 스킬을 내 칼로 만드는 법": 지난 대화에서 끼어든 순간을 찾아 린트·스킬로 바꾸게 하라. 모델이 좋아질수록 스킬은 구현 세부를 덜고 순서만 담아 작아진다.

### 1-3. 글 「마이크로소프트 CEO 나델라, 코드는 싸졌지만 어려워진 건 검증이다」

- 출처: https://maily.so/josh/posts/32z831mjon4 (1-4 영상을 Q&A 로 옮긴 글)
- 읽은 범위: 본문 전체(도입 ~ "말하는 시간보다 해 보는 시간을 늘린다" ~ 맺음, 끝의 광고 단락까지). 이미지는 캡션만. [참고] 단락이 인용한 Cowork 팀 블로그(11/2)와 Claude Code 팀 X 글은 원문을 열지 않았다.
- 요점(단락):
  - "Microsoft는 Copilot으로 …": 모델 성능이 뛰면 쓰는 형태를 빨리 바꿔야 한다. "만든 것에 정 붙이지 마세요."
  - "나델라도 배우는 검증 …": 코드 생성이 싸진 지금 어려운 건 검증. 실패가 나올 때마다 테스트 케이스로 추가하고 그 테스트가 제 역할을 하는지 확인. 일을 작게 나눠 주고 정말 끝났는지 확인. 비평은 다른 모델 계열에. [참고] 단락: Cowork 팀은 PR 전에 고친 코드를 뺀 채 새 테스트를 돌려, 그래도 통과하면 고쳤다는 증거로 치지 않는다. Claude Code 팀은 리뷰어를 더하기보다 주 리뷰어를 다듬는 편이 나을 때가 많다고 썼다.
  - "운영 로그 …": 운영 로그로 고친 게 맞는지 확인하는 고리.
  - "오래된 제품은 빌드부터 …": 브라운필드에서 가장 어려운 건 빌드와 CI/CD, 단계마다 다진다.
  - "모델은 바꿔 끼우고 …": 맥락·기억·도구는 어느 모델에도 묶지 않는다. 자체 평가가 공개 벤치마크보다 중요. 어떤 모델로 바꿔도 자체 평가 점수를 끌어올릴 수 있는지가 시금석. 똑똑함과 권한은 설계부터 떼고, 에이전트는 사고칠 수 있는 내부 직원으로 본다.
  - 그 밖: 라우터·로컬 모델, 조직 개편·채용, "더 해 보라".
