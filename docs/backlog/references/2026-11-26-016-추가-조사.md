## 2. `/until-done`은 왜 안 쓰였나

**규칙이 틀려서가 아니라, 켜 보지 않은 채 지워졌다.** 확신은 중간이다. 노트: `research_notes/…/until-done.md`

- 이 맥의 세션 기록 370개에서 `/until-done`·`/auto`를 부른 기록은 0번이다. 같은 방법으로 세면 `/task`는 입력 24번, 호출 28번이다.
- 켜는 비용이 컸다. 사용자가 직접 쳐야 했고, 끝 조건을 인자로 줘야 했고, `/goal` 한 줄을 따로 붙여 넣어야 했다(`219f092` SKILL.md `:5`, `:19`, `:21-27`).
- main 에 있던 기간은 약 43시간이다(`41037a2` → `3603f93`). 006 은 여섯 가지를 한꺼번에 지운 정리였다.
- 016 에 주는 뜻: 모드를 따로 두지 않고 기본값을 바꾸는 방향은 맞다. 하지만 선례가 규칙을 검증해 주지는 않는다. AC #11 의 측정이 유일한 검증이다.
- **새로 알게 된 것:** simplify 질문 두 번은 사용자가 11-25 에 직접 넣었다(`fa91c89`, "항상 묻도록 하라고 내가 지시했다"). AC #5 는 이것을 지운다. 기록에서는 7번 물었고, 사용자가 내용을 바꾼 것은 1번이다.

## 4. 플랜 모드 없이 "답 전에 고치지 않기"

Claude Code 공식 문서를 읽었다. 노트: `research_notes/…/edit-guard-and-approval-relay.md`

- **추천: 순서로 지킨다.** 착수 전 질문은 부모 세션에서 묻고, 답을 받은 뒤에 워크트리·브랜치·하위 세션을 만든다. 답 전에는 고칠 곳이 없다. 앞선 서베이의 추론과 문서가 맞는다.
  - 서브에이전트는 AskUserQuestion 을 쓸 수 없다. 그래서 질문은 어차피 메인 세션에서 해야 한다(sub-agents 문서).
- 도구로 막고 싶다면 플러그인 `hooks.json`의 PreToolUse 훅이 있다. 세션별 플래그 파일이 있으면 Edit·Write·Bash 를 막는 방식이다. 플래그가 남으면 막히는 위험이 있어 지금은 권하지 않는다.
- 주의: 사용자가 `askUserQuestionTimeout`을 켜 두면 답 없이 스스로 판단해 진행한다. 스킬이 통제할 수 없다.
- **승인 중계의 한계는 문서로 확인했다.** 세션 사이 메시지는 승인·동의가 되지 않는다(cross-session-messaging, agent-teams 문서). 부모가 받은 "머지해"를 하위 세션에 전해도 하위 세션은 그것을 승인으로 쓸 수 없다. 머지는 사용자가 답한 세션에서 하거나, 하위 세션의 권한 프롬프트에 사람이 답해야 한다. AC #8 에 이것을 넣어야 한다.

## 사용자가 정한 것 (2026-11-26, 이 조사를 본 뒤)

- 위 표에서 AC #8(머지는 답한 세션에서)과 AC #2 (나)(착수 전 질문을 하위 세션을 띄우기 전에 부모 세션에서)는 **넣지 않는다.** 사용자가 거절했다. 실제로 부모 세션이 전한 "머지해"로 하위 세션이 머지해 왔고 문제가 없었다. 착수 전 질문은 지금처럼 하위 세션이 묻는다. 4절의 문서 내용은 조사 기록으로만 남긴다.
- 나머지 행은 016 항목에 넣었다.
- **superpowers 를 쓰지 않는다.** 3절의 "부를지, 미리 답해 넘길지"는 필요 없어졌다. 다섯 스킬에서 필요한 규칙만 `/task`에 직접 적고, 플러그인 의존성에서 뺀다(016 AC #9).
- **simplify 는 묻지 않고 늘 찾기만 모드로 돈다.** 찾은 것은 end 의 마지막 메시지에서 고칠지 고른다(016 AC #5). 11-25 의 "항상 확인한다"는 이렇게 지킨다.
- **start 와 end 를 합친다.** `/task start` 하나가 구현부터 리뷰, 머지 질문까지 한다. `end` 모드는 없다(016 AC #12). 1절의 "end 를 진행할까요?" 6번은 이렇게 없앤다.
- **푸시:** 묻는 것은 기준 브랜치·배포 브랜치로 가는 푸시뿐이다. 그 밖의 브랜치는 묻지 않고 푸시한다. 강제 푸시 금지도 기준·배포 브랜치에만 건다.
- **기록:** 묻지 않고 정한 것은 왜 그렇게 정했는지와 함께 항목 파일에 적으면서 진행한다. 나중에 진입 모드 스킬을 만들어도 같은 기준을 따른다.
