## pstack 사본 다시 받기

보고서와 노트의 `파일:줄`은 2026-11-26 에 받은 사본 기준이다. 사본은 저장소 밖 임시 폴더에 있었으니 집에서는 다시 받는다. 마크다운만 받는다(스크립트는 받지 않았다).

```bash
D=/tmp/pstack-copy; mkdir -p "$D" && cd "$D"
curl -s "https://api.github.com/repos/cursor/plugins/git/trees/main?recursive=1" \
  | python -c "import sys,json;[print(t['path']) for t in json.load(sys.stdin)['tree'] if t['path'].startswith('pstack/') and t['type']=='blob' and t['path'].endswith('.md')]" \
  | tr -d '\r' > list.txt
while read p; do mkdir -p "$(dirname "$p")"; curl -s "https://raw.githubusercontent.com/cursor/plugins/main/$p" -o "$p"; done < list.txt
```

먼저 볼 파일:
- `pstack/skills/poteto-mode/SKILL.md`, `pstack/skills/poteto-mode/worker.md`
- `pstack/skills/principle-never-block-on-the-human/SKILL.md`
- `pstack/skills/ketchup/SKILL.md`
- `pstack/docs/guide/02-poteto-mode.md`, `pstack/docs/guide/04-design.md`

`cursor/plugins`의 main 이 바뀌었으면 줄 번호가 어긋날 수 있다.

## 더 조사할 것 (start 전에)

중요한 순서다. 결과는 016 계획의 가정에 적는다.

1. **실제로 몇 번 멈췄는지 기록으로 세기.**
   - 지금 수치(6~10 → 2~4)는 절차를 따라 센 추정이라 근거가 약하다는 지적을 받았다.
   - 이 컴퓨터의 `~/.claude/projects/C--Users-user-Documents-jihoons-j-dev-kit/*.jsonl`에서 012·013 의 create·start·end 세션을 골라, 사용자에게 묻고 멈춘 횟수를 센다. 집 컴퓨터에는 이 기록이 없을 수 있다.
   - AC #11 의 eval 기준선으로도 쓴다.
2. **`/until-done`이 왜 안 쓰였나.**
   - 006 은 여러 스킬을 한꺼번에 지우면서 "쓰지 않는 것이 많다"라고만 적었다(`006:14`). 원문은 `git show 219f092:plugins/workflow/skills/until-done/SKILL.md`에 있다.
   - 이유가 "켜야 써서"였다면 016(기본값을 바꿈)이 맞는 답이다. "규칙 자체가 맞지 않아서"였다면 016 도 다시 봐야 한다.
3. **superpowers 의 숨은 질문을 어떻게 끄나** (AC #9).
   - brainstorming, test-driven-development, receiving-code-review, finishing-a-development-branch 가 어디서 묻는지는 `research_notes/.../fact-check.md` B 절에 줄 번호가 있다.
   - 부르는 쪽 지시문으로 미리 답해 주면 되는지, 아니면 그 스킬을 부르지 않고 필요한 부분만 절차에 둘지 정한다.
   - superpowers 버전은 `~/.claude/plugins/cache/anthropic-plugin-directory/superpowers/7.0.2-…`였다.
4. **플랜 모드 없이 "답 전에 아무것도 고치지 않기"를 어떻게 지키나.**
   - 플랜 모드는 도구 차원에서 편집을 막았지만, 이제는 지시문뿐이다.
   - Claude Code 공식 문서에서 쓸 수 있는 장치(권한 모드, 훅 등)가 있는지 본다. 없으면 지시문으로 두고 eval 로 확인한다.
5. **의견이 갈린 것을 정한다.**
   - 브라우저 도구가 없을 때 멈출지, 적고 계속할지
   - 공식 스킬 설치를 매번 묻지 않고 진행할지
   - 보고서 7절 표에 각 의견이 있다.
6. **blast-radius 류.** 012 의 🔁 5건이 모두 "규칙을 옮기며 남길 것까지 빠진" diff 밖 실패였다(`012:619`). end 리뷰 지시문에 한 줄로 막을지 본다. 016 범위 밖이면 새 항목으로 뺀다.
