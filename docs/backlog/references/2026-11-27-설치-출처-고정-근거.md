# 설치 출처 고정: 019 의 근거 (2026-11-27)

2026-11-27 에 main 의 변경(`b4f6a01`부터 `c1d5611`까지)을 리뷰 에이전트 셋과 판정 에이전트 하나가 봤다. 그 가운데 `/kit-setup`이 받는 스킬과 플러그인의 출처에 관한 것만 여기에 옮긴다. 백로그 019 가 이 글을 근거로 삼는다.

표시: **[확인]**은 명령 출력이나 파일을 직접 본 것, **[추론]**은 본 것에서 미룬 것, **[확인 못 함]**은 보지 못한 것이다.

## 확인한 것

- **[확인]** `claude plugin marketplace add --help`의 옵션은 `--claudeai`, `--json`, `--scope`, `--sparse`뿐이다. 받는 판(브랜치, 태그, 커밋)을 고정하는 옵션이 없다.
- **[확인]** `claude plugin install --help`의 `--scope` 기본값은 `user`다. `marketplace add`도 기본이 user 다. `/kit-setup`의 표는 모두 `--scope project`를 준다.
- **[확인]** `claude plugin marketplace remove --help`에 `--scope`가 있다. 설치가 실패했을 때 더해 둔 마켓플레이스를 지울 수 있다.
- **[확인]** `/kit-setup` 표의 `npx -y skills@1.7.5 add <저장소>` 두 줄은 CLI 의 버전만 적고, 저장소는 판 없이 가리킨다.
- **[확인]** skills CLI 1.5.23(1.7.5 가 아니다)의 README 와 코드:
  - `skills` 자체에 확인 프롬프트를 넘기는 `-y`가 있다. `npx -y`의 `-y`는 npx 의 확인만 넘긴다.
  - 기본 설치 범위는 프로젝트다.
  - `skills-lock.json`과 `.agents/skills/`에도 쓴다.
- **[확인]** Supabase 공식 플러그인 0.1.17 에는 스킬 `supabase`와 `supabase-postgres-best-practices`가 함께 온다. 같이 오는 MCP 설정에는 `read_only`도 `project_ref`도 없다.
- **[확인]** 012 의 Final Summary 가 `skills add`의 내용이 고정되지 않는 것을 기존 문제로 적었다(`docs/done/012-chore-official-skills-narrow-stack.md`).

## 추론

- **[추론]** `marketplace add <owner/repo>`는 그 저장소 기본 브랜치의 머리를 따른다. 판을 고정하는 옵션이 없기 때문이다.
- **[추론]** `skills add`는 스킬의 내용을 그 저장소의 머리에서 받는다. 1.5.23 의 동작에서 미룬 것이다.
- **[추론]** `@anthropic-plugin-directory`는 claude.ai 가 호스팅한다. `marketplace add --help`의 `--claudeai` 설명에서 미룬 것이다.

## 확인 못 한 것

- skills CLI 1.7.5 가 비대화형 실행에서 확인 프롬프트로 멈추는지, `.claude/skills/` 밖의 어디에 쓰는지, 커밋으로 고정한 소스를 받는지. npm 에서 받아야 해서 돌리지 않았다.
- `marketplace add`의 `<source>`가 `#<ref>` 같은 판 표기를 받는지. 도움말에는 없다. 받는다면 019 의 전제가 바뀐다.
- `@anthropic-plugin-directory`에서 받는 플러그인(`frontend-design`, `typescript-lsp`, `supabase`)의 판이 어떻게 정해지는지.
- `claude plugin list`가 다른 프로젝트의 project 범위 설치까지 보여 주는지.
- 워크트리에서 `--scope project`로 깔면 어디에 쓰이는지, 워크트리를 지운 뒤에도 켜지는지.
- 세션 중에 넣은 `.claude/skills/`가 그 세션에서 바로 잡히는지.
- Supabase MCP 를 한 프로젝트로 좁히는 매개변수의 이름.
