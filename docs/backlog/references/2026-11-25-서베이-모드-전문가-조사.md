# 서베이 모드: 전문가들은 어떻게 하나, 어떻게 고칠까 (2026-11-25)

대상: `plugins/workflow/skills/task/references/create.md` "서베이 모드" 절 (main 65c6df9).
표기: **[직접]** = 이 세션이나 하위 에이전트가 원문 페이지를 직접 읽음. **[요약만]** = 원문 일부를 요약으로만 봄.

## 결론 요약

지금 서베이 모드는 저장소 안 자료(오류 로그, 백로그, `gh issue list`, 사용 데이터)만 읽고, 후보를 한 번에 고른다. 바깥 자료는 사용자가 URL 을 줄 때만 본다. 조사한 실무자들은 공통으로 다섯 가지를 더 한다.

1. 목표를 결과와 조사 질문으로 먼저 쪼개고, 질문마다 각도(안쪽 자료, 바깥 자료)를 정한다.
2. 바깥을 직접 찾아 읽는다. 넓은 검색에서 시작해 좁히고, 1차 출처를 SEO 글보다 앞에 둔다.
3. 각도마다 따로 읽고(병렬), 자료마다 먼저 메모한 뒤 자료를 가로질러 묶는다.
4. 묶은 범주를 세고, 새 자료가 새 범주를 만들지 않을 때 멈춘다.
5. 고른 후보를 다른 쪽이 거짓 양성인지 걸러 낸 뒤 사람에게 보인다.

또 지금은 후보 목록이 대화에만 남는다. 이 저장소 규칙("백로그 항목이 근거로 삼는 조사 보고서는 `docs/backlog/references/`")과도 맞지 않는다.

## 3. 고칠 제안 (중요도 순)

### 1. 바깥 조사를 기본으로

- 바꿀 것: 1단계 "주지 않았으면 저장소에서 찾는다"를 "안쪽과 바깥을 모두 찾는다"로. 바깥 기본 각도: 쓰는 도구·라이브러리의 공식 문서·변경 기록·이슈, 같은 일을 하는 다른 도구·선례, 그 분야 실무자의 글·발표. 사용자가 준 URL 은 출발점이지 범위 한정이 아니다. 바깥을 빼려면 사용자가 `--internal`(가칭)이라고 말할 때만.
- 검색 규칙: 짧고 넓은 검색에서 시작해 좁힌다. 공식 문서·원저자 글·저장소 원문을 요약 블로그보다 앞에 둔다. 검색 결과 요약만 본 것은 근거로 쓰지 않거나 **[검색]**으로 표시한다.

### 2. 목표를 조사 질문과 각도로 먼저 쪼개고 한 줄로 보여 주기

- 바꿀 것: 새 0단계. 목표를 "무엇이 나아지면 됐다고 하나"(결과) 한 문장과 조사 질문 2~5개로 적고, 질문마다 안쪽·바깥 각도를 정한다. 사용자에게 보여 주되 승인을 기다리지 않고 바로 진행한다(고치고 싶으면 끼어들게).
- 노력은 목표 크기에 맞춘다: 좁은 목표면 각도 1~2개, 넓으면 여러 개.

### 3. 각도별 하위 에이전트 병렬 수집, 원문 메모는 파일로

- 바꿀 것: 각도마다 하위 에이전트를 띄운다. 지시문에 목표·출력 형식·쓸 출처·경계를 넣는다. 각 에이전트는 자료마다 메모(무엇을 봤나, 짧은 원문 인용, 위치·URL, 읽은 날짜, [직접]/[검색])를 `.claude/.local/` 아래 파일에 쓰고 경로만 돌려준다.
- "날것을 직접 읽는다"와 충돌하지 않게: 후보의 근거로 올리는 주장은 메인 세션이 그 원문을 다시 열어 확인한다(사용자 메모리 "근거는 원문에서"와 같은 방향).

### 4. 메모 → 범주 → 세기 → 포화

- 바꿀 것: 2단계 "후보 고르기"를 이렇게 바꾼다. 자료마다 메모를 먼저 쓰고(지금 1단계가 그냥 "읽기"), 메모를 가로질러 범주로 묶고, 범주마다 근거 수를 센다. 새 자료를 더 읽어도 범주가 생기지 않으면 수집을 멈춘다. 범주는 메모에서 만들고 미리 정한 틀에 끼우지 않는다.
- 후보는 해법이 아니라 문제·필요로 먼저 적고, 해법은 그 아래 한 줄로.

### 5. 거짓 양성 거르기를 다른 쪽에

- 바꿀 것: 후보를 보이기 전에, 메인 세션이 아닌 판정 에이전트가 후보마다 "근거가 주장을 받치나, 이미 있는 항목·이미 고쳐진 것과 겹치나, 출처가 1차인가"를 본다. 떨어진 후보는 "제안하지 않는 것"에 이유와 함께. `end.md` 판정 에이전트와 같은 방식이라 저장소 안에 선례가 있다.

### 6. 조사 보고서를 남기고 항목이 가리키게

- 바꿀 것: 3단계에서 후보 목록을 보고서 파일로 쓴다. 형식은 이 저장소에 이미 있는 서베이 보고서(`docs/backlog/references/바깥 동향 아이디어 소스 서베이.md`)와 같게: 확인 날짜, 결론 요약, 후보 표(제목, 문제, 근거와 [직접]/[검색], 크기·빈도, 확인 수단), 제안하지 않는 것과 이유, 읽지 못한 것. 고른 후보가 있으면 보고서를 `docs/backlog/references/`에 두고 첫 항목 커밋에 넣고, 항목마다 그 경로를 적는다(CLAUDE.md 규칙). 고른 것이 없으면 `.claude/.local/reports/`에.

### 7. 후보에 크기와 목표 영향

- 바꿀 것: 후보마다 "얼마나 자주·몇 곳에서(근거 수)", "목표에 얼마나 닿나"를 한 줄씩. 점수 공식은 만들지 않는다(Torres: 요인들은 서로 맞지 않는다).

### 함께 할 것: eval

- 지금 서베이 eval 은 트리거만 잰다(`plugins/workflow/evals/trigger-real/y07·y11·y12`). URL 없이 목표만 줬을 때 바깥을 검색하는지, 보고서에 [직접]/[검색]과 출처가 있는지, 이미 있는 항목과 겹치는 후보를 걸러 내는지를 보는 동작 eval 을 하나 더한다. 고친 판과 지금 판을 비교한다(008 의 방식).
