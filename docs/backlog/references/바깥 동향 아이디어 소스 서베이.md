# 바깥 동향 아이디어 소스 서베이

확인 날짜: 2026-11-20 (모든 항목 같음). 표기: **[직접]** = 페이지·API를 직접 열어 확인, **[검색]** = 검색 결과 요약만 봄.

## 결론 요약

에이전트가 로그인 없이 기계적으로 읽을 수 있고 이 저장소(Claude Code 플러그인·스킬·워크플로)와 맞는 소스는 다섯 곳이다. GitHub REST API(토픽 검색, 별, 이슈), `anthropics/claude-code`의 기능 요청 이슈(👍 순 정렬), Claude Marketplace의 플러그인 상세 페이지(설치 수), skills.sh 리더보드(설치 수, 24시간 트렌딩), HN Algolia API(점수, 댓글)다. Reddit 은 자동으로 읽을 수 없었고(WebFetch 거부, API 는 승인제), claude.ai/directory 와 SkillsMP 는 403 으로 막혔다. 선례(GitHub Agentic Workflows 리서치·태스크 마이너, 주간 다이제스트, 경쟁·수요 스킬)에서 공통으로 보이는 것은 여섯 가지다. 항목마다 URL 근거를 단다. 관심 주제나 경쟁 대상을 저장소 안의 마크다운에 적어 두고 그것으로 거른다. 바깥 동향은 주 1회 돈다. 웹을 읽는 쪽은 쓰기 권한이 없고, 쓰기와 승인은 따로 둔다. 실행당·소스당 상한을 두되 숫자는 사례마다 다르다. 소스가 설정돼 있지 않으면 실패하지 않고 줄여서 돈다. 이 저장소에는 "프로젝트에 커밋된 마크다운에 소스 목록, 없으면 바깥 관점은 건너뜀"이 공통분모에 맞는다. `/lead`가 설정을 CLAUDE.md 에서 읽는 관례와도 맞는다.

## 3. 설계에 쓸 것 (공통분모만)

**(a) 바깥 근거 적기:** 항목마다 원본 URL 을 단다(Task Miner, Capuano, Langfuse, demand-signal). 날짜는 Capuano 가 발행일을, competitive-brief 가 분석 날짜를 적는다. 그러니 `URL · 확인 날짜` 한 쌍이면 공통분모를 덮는다. 링크를 받은 쪽이 다시 확인하는 것도 두 곳에 있다: Langfuse 는 링크 형식을 평가하고, demand-signal 은 없는 이슈 번호를 지운다. 이 저장소의 scout 2단계(부른 세션이 근거를 열어 확인)와 같은 구조라, URL 근거도 같은 단계에서 열어 보면 된다. 수치(별, 설치 수)는 바뀌므로 확인 날짜와 함께 적는다. 설치 수 지표는 소스마다 뜻이 다르다(텔레메트리, 복사 클릭, 별). 그래서 지표 이름을 함께 적는다.

**(b) 관련성 거르기:** 관심 주제·경쟁 대상 목록을 미리 적어 두고 그 안에서만 찾는다(Shing Lyu 주제 5개, ccc `.pm/config.md`의 포지셔닝, competitive-brief 의 범위 질문). Task Miner 는 포함·제외 기준을 프롬프트에 명시한다. 이미 추적 중인 것과 겹치면 뺀다(Task Miner 검색·캐시, ccc `/pm:sync`, Shing Lyu 지난 노트). 이 마지막 것은 지금 scout 의 "항목·제안함·기각과 겹치면 제안하지 않음"과 같다. 점수식은 사례마다 달라 공통 기준이 없다(**근거 없음**).

**(c) 실행 주기:** 바깥 동향을 읽는 선례 4개(Weekly Research, Shing Lyu, Capuano, Langfuse)는 모두 주 1회다. 매일 도는 것은 내부 디스커션을 읽는 Task Miner 뿐이다. 스킬형 선례는 요청할 때 돈다. 이 저장소의 세션 안 예약은 7일 뒤 만료된다(`plugins/workflow/skills/lead/references/schedule.md:36`). 주 1회로 예약하면 만료 전에 한 번쯤 돈다는 점은 알려야 한다. 저장소 scout 보다 바깥 조사를 더 드물게 돌려야 한다는 근거는 위 선례들뿐이고, 두 주기를 나눈 사례는 찾지 못했다(**근거 없음**).

**(d) 프롬프트 인젝션 대응:** 공통은 세 가지다. 첫째, 웹을 읽는 에이전트는 쓰기 권한이 없고 쓰기는 별도 단계가 한다. gh-aw 는 safe outputs 로 쓰기를 버퍼링한 뒤 범위가 제한된 작업이 수행하고, 이 저장소의 backlog-scout 도 파일을 쓰지 않는다. 둘째, 접속 도메인을 허용 목록으로 묶는다. gh-aw 는 방화벽과 `network.allowed`를 쓰고, 허용 밖 URL 은 `(redacted)`로 바꾼다. 셋째, 원문을 그대로 넘기지 않는다. Claude Code WebFetch 는 별도 모델 호출이 읽은 답만 돌려주고, 공식 문서는 "신뢰할 수 없는 내용을 바로 넘기지 말 것"을 권한다. 이 밖에 Weekly Research 는 막히면 우회하지 말고 보고하라고 지시한다. 근거: [직접] https://github.github.com/gh-aw/introduction/architecture/ , https://code.claude.com/docs/en/security

**(e) 실행당 상한:** 모든 gh-aw 선례는 상한을 둔다. 출력 종류마다 기본 max 1이다([직접] https://github.github.com/gh-aw/reference/safe-outputs/). 이슈는 5개(Task Miner), 전체 15개와 소스당 4개(Capuano), 주제당 3~5개(Shing Lyu), 수집 200개(demand-signal)이고 시간 제한은 15~20분이다. 할 일이 없으면 "없음"을 허용한다(`noop`). 공통은 "실행당 상한 + 소스(주제)당 상한 + 없음 허용"이다. 숫자 하나로 모이는 공통값은 없다(**근거 없음**). 이 저장소의 "관점마다 10개"는 README 에 적힌 대로 정해 둔 고정값이다.

**(f) 프로젝트별 소스 설정:**

| 선례 | 설정 위치 · 형식 | 없을 때 |
| --- | --- | --- |
| Shing Lyu (gh-aw) | 저장소의 `.github/workflows/weekly-research.md`. frontmatter `network.allowed`에 도메인, 본문에 주제 | 기본 네트워크 목록(`defaults`) |
| Capuano (gh-aw) | 저장소의 `.github/workflows/weekly-news-digest.md`(RSS 7개. frontmatter 인지 본문인지는 미기재) | 미기재 |
| ccc product-management | 저장소의 `.pm/config.md`(포지셔닝·가중치), `.pm/competitors/`. 커밋 가능 | `/pm:landscape`가 경쟁사 5개를 스스로 찾는다 |
| last30days | 키는 사용자 단위 `~/.config/last30days/.env`, 소스는 `INCLUDE_SOURCES`와 실행 인자 | 키 없이 되는 소스(Reddit·HN·GitHub)와 웹만 쓴다 |
| demand-signal, competitive-brief | 파일 없음. 실행 인자나 질문 | demand-signal 은 인자 필수, competitive-brief 는 묻는다 |
| Anthropic plugin-dev `plugin-settings` | `.claude/<플러그인>.local.md`. YAML frontmatter + 본문. gitignore 권장(개인용) | 훅은 바로 끝난다. 기본값을 두라고 권한다 |

공통분모는 둘이다. 첫째, 소스·관심사는 **프로젝트 저장소 안의 마크다운**에 적는다(gh-aw 두 사례, ccc). 사용자 단위 파일은 키 같은 비밀에만 쓰였다(last30days). 둘째, **없으면 실패하지 않고 줄여서 돈다**(기본값, 키 없이 되는 소스만, 건너뜀). 근거: [직접] https://raw.githubusercontent.com/anthropics/claude-plugins-official/main/plugins/plugin-dev/skills/plugin-settings/SKILL.md 와 위 선례 URL.

이 저장소에 대입하면 이렇다.
- `/lead`는 프로젝트 설정을 CLAUDE.md 에서 읽고, 없으면 기본값을 쓴다(`plugins/workflow/skills/lead/SKILL.md:40-47`). 소스 목록도 같은 곳에서 읽으면 "저장소 안 마크다운" 공통분모와 이 저장소의 관례가 둘 다 맞는다. 없을 때는 바깥 관점만 건너뛰고 지금처럼 저장소 근거로 돈다. 이것이 "줄여서 돈다"에 해당한다.
- 크기: CLAUDE.md 는 매 세션 컨텍스트에 들어간다. 공식 문서는 파일당 200줄 이하를 권하고, `@` import 는 같이 로드되므로 비용을 줄이지 않는다고 한다([직접] https://code.claude.com/docs/en/memory). 그래서 소스가 몇 줄이면 `## 작업 설정`에 두는 것이 관례에 맞다. 길어지면 ccc 처럼 저장소 안 별도 파일에 두고, CLAUDE.md 에는 그 경로를 백틱으로(import 하지 않게) 적는 방식이 문서와 충돌하지 않는다. 몇 줄부터 분리하라는 기준은 **근거 없음**.
- `.claude/<플러그인>.local.md`(plugin-settings 방식)는 gitignore 되는 개인 설정이다. 소스 목록을 팀과 같이 쓰려면 맞지 않는다. 선례 중 소스를 공유한 것(gh-aw, ccc)은 모두 커밋되는 파일이었다.
- 소스 목록이 (b) 관련성 필터와 (d) 도메인 허용 목록을 겸한다. Shing Lyu 는 `network.allowed` 하나로 둘 다 했다. 목록 밖 사이트를 읽지 않는 규칙으로 쓸 수 있다.

## 4. 확인 못 한 것

- claude.ai/directory, skillsmp.com: WebFetch 403 이라 내용·자동 읽기 여부를 확인하지 못했다.
- Reddit: WebFetch 가 거부했다. API 승인제·비인증 `.json` 차단은 미러·블로그로만 봤다.
- Claude Marketplace 의 공개 API, 약관상 자동 수집 조항, 설치 수 갱신 주기.
- `claude-plugins-official`에 설치 수 통계 파일이 있다는 주장(유출 소스 미러에만 있음).
- skills.sh API 의 비인증 호출 가능 여부와 이용 약관.
- HN Algolia API 요청 한도.
- GitHub Trending 공식 API(찾지 못함).
- claudepluginhub·claudemarketplaces 의 API.
- X, Product Hunt, Discord 는 조사하지 않았다.
- 선례 중 실행 비용을 밝힌 곳이 없다.
