## 1. pstack 은 언제 묻나 [직접]

기본은 묻지 않는다. 근거는 "되돌릴 수 있는 일은 정하고 진행한 뒤 보여 준다"이다(P `principle-never-block-on-the-human/SKILL.md:9-14`, `poteto-mode/SKILL.md:68,76`).

멈추거나 묻는 곳을 전부 모으면 다음과 같다.

| 종류 | 위치 |
| --- | --- |
| 되돌릴 수 없는 쓰기(force-push, 배포, 데이터 삭제, 바깥 메시지) | `poteto-mode/SKILL.md:78`, `worker.md:7`, `never-block:13` |
| 실험으로 정할 수 없는 제품·취향 결정 | `playbooks/autonomous-run.md:9`, `multi-phase-plan.md:6`, `sharpen/SKILL.md:16`, `never-block:15` |
| 진짜 막다른 길 | `autonomous-run.md:9,11`, `hillclimb.md:18` |
| 머지·소유자 승인, 계획 뒤의 "go" | `babysit.md:3,10`, `autopilot-stack.md:5`, `autopilot-full.md:7`, `multi-phase-plan.md:4,9` |
| 긴 실행 전에 체크포인트 한 번 | `figure-it-out/SKILL.md:23` |
| 이유를 대야만 사용자에게 재현 요청 | `bug-fix.md:7` |
| 기준선이 틀려 보일 때 | `visual-parity.md:6` |
| 커밋 안 된 작업을 지울 때 | `worktree-cleanup.md:4` |
| 의도가 불분명할 때 | `interrogate/SKILL.md:13` |
| 스킬 수정 승인, 설정 | `reflect:15`, `no-comments:23`, `setup-pstack:32,40`, `automate-me:17,44` |
| 보안·데이터 쪽 bot 지적 | `references/bugbot-triage.md:11` |

질문 대신 쓰는 것:
- **실행으로 확인한다.** 정할 수 있는 갈림길은 프로토타입으로 정한다(`poteto-mode:21`, `prototype.md`, `docs/guide/04-design.md:75`). 사람이 직접 확인하게 넘기지 않는다(`poteto-mode:104`).
- **결정을 남긴다.** TSV 결정 기록에 감사와 다른 회사 모델의 검토를 붙인다(`show-me-your-work:13-22,57-74`).
- **작성자가 아닌 쪽이 판정한다**(`shipping.md:5`, `figure-it-out:41-42`).
- **한 번에 묻는다.** 쌓인 결정은 `/ketchup`이 모은다. 사용자만 할 수 있는 일만 올리고, 항목마다 추천·근거·위험을 붙인다(`ketchup:17,29-31`).
- **하위 에이전트는 묻지 않는다.** 질문 도구를 쓰지 않고, 브리프의 기준 위에 게이트를 더하지 않는다(`worker.md:4,7`).
- **계획 스킬이 없다.** 계획은 요청했을 때만 쓰고, 그때만 "go"를 기다린다(`guide/04:97`, `multi-phase-plan.md:9`).
- **세션 단위로 덮어쓴다.** "자러 간다", "멈추지 마"면 계속한다(`poteto-mode:80`).

## 3. 계획 승인을 없애려면

**승인이 실제로 바꾼 것 [직접].**
- 범위가 바뀐 승인: 008:25,84(3절 5~7 추가), 010:99(AC #6 추가, #4 확장), 012:157(Supabase 조건).
- 그대로 통과한 승인: 009:65 "진행", 011:49 "추천안대로".
- 기록이 있는 다섯 번 중 세 번은 승인 때 범위가 바뀌었다(013 은 승인 기록을 못 찾았다).
- 플랜 모드는 사용자가 012:74 에서 "공식 플랜 모드를 쓰는게 맞아"라며 넣은 것이다. 이번 결정은 이를 뒤집는다는 점을 기록해 둘 만하다.

**더 있어야 할 것.**
1. **착수 전 질문 한 번.** start.md:45 와 스택 "물을 것"을 한 메시지로 묻는다. 질문이 없으면 멈추지 않는다. 사용자가 말한 "중요한 설계는 초기에 질문"의 자리가 이것이다.
2. **계획은 보여 주되 기다리지 않는다.** 목표와 가장 작은 변경을 다시 말하고 진행한다(P `poteto-mode:19`). create --survey 1단계(create.md:97)가 이미 같은 방식이다. 하위 세션이면 부모가 이 요약을 전한다(SKILL.md:46 경로) (추론).
3. **계획과 정한 것을 항목 파일에 남긴다.** start.md:68 그대로 두고 "승인된"만 뺀다. 선례는 004 의 `Ruling:`(004:61,92)이다.
4. **"범위가 커지면"(start.md:78)을 확인할 수 있게 정의한다.** AC 밖의 동작, 새 의존성이나 도구 설치, 스키마·공개 API·삭제, CLAUDE.md·설정 변경에서만 멈춘다.
5. **되돌릴 수 없는 일의 목록을 적는다.** 푸시, 원격 DB, 배포, 지우기, 바깥 메시지(P `poteto-mode:78`, 004:20).
6. **"승인된 계획"에 기댄 문장을 고친다.**
   - `docs/review-principles.md:8`은 "계획 때 사용자가 정한 것"이라 리뷰가 에이전트의 가정까지 보호하게 된다. AC 와 사용자가 답한 것으로 좁혀야 한다.
   - 같은 전제를 쓰는 곳: start.md:3,58,68, create.md:50(템플릿), mockup.md:48.
   - frontend-start-check 의 "계획 전에 할 것"은 플랜 모드에서 캔버스를 만들 수 없어서 생겼다(006:79). 그 이유가 사라진다.

**위험.**
- 방향이 틀린 것을 end 리뷰에서야 알게 된다. 구현이 빠르다는 사용자 판단이 맞으면 손실은 작다 (추론).
- 위 6 을 고치지 않으면 판정 에이전트가 에이전트의 가정을 "정한 것"으로 보고 지적을 뺀다.
- 그대로 남는 안전장치: Stop 훅, AC 판정 에이전트(start.md:90-92), end 리뷰, 머지 승인.

| 안 가져올 것 | 하위 세션이 질문 도구를 쓰지 않기 | `worker.md:7`. 사용자가 하위 세션과 직접 대화하는 구조(T/SKILL.md:44-48)와 맞지 않는다 | ○ |

## 5. 진입 스킬을 만든다면

**담을 것.**
- 사용자만 부르게 한다(`disable-model-invocation: true`, P `poteto-mode:4`와 같다).
- 위 세 갈래 규칙과 되돌릴 수 없는 일의 목록.
- 질문 형식: 한 메시지에 번호를 붙여, 각 항목에 추천과 무엇이 바뀌는지를 쓴다.
- 결정을 남길 곳: 항목 파일, 항목이 없으면 끝 보고.
- 백로그 항목 이야기면 `/task`로 보내고, 아니면 바로 한다.
- "멈추지 마"면 취향 결정도 추천대로 정하고 기록한다.

**뺄 것.**
- 플레이북 목록, 원칙 색인, 모델·서브에이전트 기본값, 글쓰기 규칙(015 writing 플러그인과 겹친다), Cursor 전용 기능.

**주의 [직접 + 추론].**
- 별도 모드 스킬은 004 에서 만들었다가 006 에서 쓰지 않아 지웠다.
- 그래서 규칙의 본체는 `task` SKILL.md 4절(늘 적용됨)과 절차 파일의 질문 지점에 넣고, 진입 스킬은 그것을 /task 밖에서도 켜는 얇은 껍데기로 두는 편이 덜 버려진다.

## 6. 가장 중요한 세 가지

1. **언제 묻나를 단계가 아니라 종류로 가른다.** 지금은 create 승인, 계획, simplify, 리뷰, 머지마다 멈춘다. 되돌릴 수 있고 실행으로 정할 수 있으면 정하고 기록한다. 취향이면 착수 전과 끝에 한 번씩 모아 묻는다. 되돌릴 수 없으면 멈춘다.
2. **계획 승인이 빠지면 그 무게가 create 의 AC 승인과 end 판정으로 옮겨 간다.** 기록상 승인 다섯 번 중 세 번이 범위를 바꿨다. "범위가 커지면"의 정의와 `review-principles.md:8` 같은 "승인된 계획" 전제를 함께 고쳐야 성립한다.
3. **결정은 사람이 나중에 읽는 곳(항목 파일)에 남긴다.** 사후에 바로잡을 수 있어야 묻지 않아도 된다. Final Summary 의 "사용자가 바로잡은 것"이 이미 그 고리다. 새 모드를 따로 만들기보다 기본 절차를 바꾼다(004→006 의 교훈).
