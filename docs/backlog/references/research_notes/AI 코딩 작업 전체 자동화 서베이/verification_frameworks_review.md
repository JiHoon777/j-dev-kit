## 보고서가 반드시 반영할 수정 사항

1. **METR reward hacking "합산 1~2%"를 삭제한다.** 원문 수치는 RE-Bench 30.4%(39/128), HCAST 0.7%다. "significant underestimate"는 Claude 3.5 Sonnet 방법 비교에서 나온 말이라고 밝힌다.
2. **Greptile "PR 단위 100/64/57/36/0%"를 고친다.** 이는 High 심각도 버그의 catch rate다. 인용 URL(`ai-code-review-evaluation`)은 404이므로 `greptile.com/benchmarks`로 바꾼다.
3. **에이전트 PR 수용률의 논문 귀속을 바로잡는다.**
   - 85.8/71.3/55.0%는 2602.04226 Table 1이다(AIDev-pop ≥100 star). "AIDev 전체"가 아니다.
   - 77.9/71.9/68.0%는 2602.08915다. 태스크 유형으로 층화한 연구이고, 걸러 낸 PR 7,156개가 대상이다.
   - 84.3/73.5/43.0%는 2607.21832 Table 3의 GLMM 추정 확률이다. 원시 비율이 아니고, 출처는 alphaxiv가 아니라 PDF로 바꿀 수 있다.
   - "Claude Code 거부는 맥락 때문이지 결함 때문이 아니다"는 근거를 찾지 못했으니 뺀다.
4. **ImpossibleBench 프롬프트 효과를 일반화하지 않는다.** 93%(논문 본문은 92%)에서 1%로 줄어든 것은 Conflicting-LiveCodeBench에서만이다. SWE-bench 변형에서는 66%에서 54%로만 줄었다. 모니터 탐지율은 LiveCodeBench 86–89%, SWE-bench 42–65%다.
5. **Anthropic Code Review 정보를 정리한다.** $15–25는 1차 출처(Anthropic 블로그)로 확인됐으니 [미검증]을 뗀다. "확신도 80% 이상만 게시"는 근거를 찾지 못했으니 삭제한다. 현재는 GA라는 점을 덧붙인다.
6. **Bugbot 수치의 출처를 짝지어 쓴다.** GA 시점(2025-07)은 "over 50%"다. 52% → 70%+ → 76% → nearing 80%(2026-04)는 각각 다른 글에서 나온다. PlanetScale 80%는 Cursor가 쓴 고객 사례 글의 서술이다.
7. **Uvik 벤치마크 수치는 원문과 일치한다.** 다만 Python 아웃소싱 회사가 자체로 낸 콘텐츠 마케팅 성격의 벤치마크다. 비공개 고객 코드를 썼고, 동료 심사가 없고, ±10pt noise band가 있다. 보고서는 이를 명시하고 핵심 근거가 아니라 방향성 참고로만 써야 한다.
8. **Spec Kit의 "living, capability-level specs"는 외부 블로그 글이다**(Alfredo Perez, 2026-10-15). GitHub 공식 방향처럼 쓰지 않는다. developertoolkit의 "a person drives each stage" 인용부호도 뺀다.
9. **Claude Code 무인 실행 체크리스트는 다섯 질문이다**(세 가지가 아니다). Code Review의 REVIEW.md를 base 브랜치에서 읽는 "이유(프롬프트 주입 방지)"는 문서에 없는 추론이다.
10. **경미한 수정과 확인 결과 반영.**
    - Tencent false positive 비율은 75.8%다.
    - METR SWE-bench 노트의 PR 수는 296(본문)과 329(부록)가 엇갈린다는 점을 주석으로 단다.
    - Böckeler 글 게시일 2025-10-15를 확정으로 바꾼다.
    - METR RCT의 [원문 미재확인]을 뗀다.
    - Kiro의 EARS와 Autopilot/Supervised는 1차 문서에 없으니 쓰지 않는다.
    - BMAD v7은 11-20 현재 아직 preview alpha다.
    - StrongDM 인수는 "2026-01 발표, 2026-03 완료"로 쓴다(1차 출처 미확인).
