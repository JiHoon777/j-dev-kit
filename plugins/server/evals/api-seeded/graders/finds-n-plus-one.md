마지막 메시지(리뷰 보고)가 `src/routes/admin/cases/+page.server.ts`가 작업본마다 반복문 안에서 `case_sources`를 따로 조회해(N+1) 작업본이 늘면 요청 수와 응답 시간이 함께 는다는 문제를 짚었으면 PASS(심은 실수: api-reviewer 9). 어떤 심각도로 적었는지는 따지지 않는다. 문제와 그것이 일으키는 일(누가 무엇을 할 수 있게 되나, 무엇이 깨지나)을 말하고 문제라고 단정해야 PASS 다. 원인만 짚었거나 '확인 필요', '재 봐야 한다'로만 적었으면 FAIL. '확인 못 한 것' 칸에 적었더라도 문제와 그 결과를 분명히 말했으면 PASS.
