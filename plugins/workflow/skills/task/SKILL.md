# task

인자: `$ARGUMENTS`

## 1. 모드 고르기

인자의 첫 단어로 모드를 고르고, 나머지는 모드에 넘긴다.

| 첫 단어 | 모드 | 절차 파일 |
| --- | --- | --- |
| `create` | 백로그 항목 하나 쓰기 | `${CLAUDE_SKILL_DIR}/references/create.md` |
| `start` | 항목 하나 계획하고 구현하기 | `${CLAUDE_SKILL_DIR}/references/start.md` |
| `end` | 리뷰, 수정, 마무리, 머지 | `${CLAUDE_SKILL_DIR}/references/end.md` |

- 첫 단어가 셋 중 어느 것도 아니면 이 표를 보여 주고 묻는다. 사용자가 직접 치지 않고 요청을 보고 부를 때는 요청에 맞는 모드와 인자를 정해 부른다.
- 2절에서 어디서 할지 정한 뒤, 이 세션에서 하게 되면 고른 모드의 절차 파일 하나만 Read 도구로 끝까지 읽고 그대로 따른다. 절차 파일의 `<task-scripts>`는 `${CLAUDE_SKILL_DIR}/scripts`다.

## 2. 어디서 하나

- **`end`:** 이 세션에서 한다. 작업한 세션(`start`가 띄운 세션)에서 부른다.
- **`create`, `start`에 `--here`가 있으면:** 떼어 내고 이 세션에서 한다.
- **그 밖의 `create`, `start`:** 하위 세션을 띄운다.
  1. 사용자가 열어 보고 직접 대화할 수 있는 세션을 새로 시작하는 도구(예: 데스크톱 앱의 `start_session`)가 없으면, 이 세션에서 한다고 한 줄 알리고 절차를 따른다.
     - `create`는 이 세션이 기준 폴더의 기준 브랜치에 있을 때만 띄운다. 워크트리 안이거나(`git rev-parse --path-format=absolute --git-dir --git-common-dir`의 두 줄이 다르면) 다른 브랜치면 이 세션에서 하고, 항목 커밋이 지금 브랜치에 들어간다고 알린다. 같은 폴더를 두 세션이 함께 쓰면 커밋과 인덱스가 섞인다.
  2. `start`는 먼저 이 세션에서 항목을 찾는다(`start.md` 1단계의 "항목 찾기"). 이 항목의 `w/` 브랜치가 이미 있으면 띄우지 않고, 그 브랜치에서 일하던 세션에서 이어 가라고 알린다. 그 세션이 없으면 이 세션에서 `start.md`대로 그 브랜치를 이어 간다.
  3. 세션 하나를 띄운다. 사용자가 시킨 일이니 제안으로 올리지 않고 바로 시작한다.

     | 모드 | 세션 |
     | --- | --- |
     | `create` | 이 폴더 그대로(워크트리 없이) |
     | `start` | 기준 브랜치에서 딴 새 워크트리, 브랜치 이름 `w/<.md 를 뺀 항목 파일 이름>` |

  4. 그 세션은 이 대화를 볼 수 없다. 지시문은 "`task` 스킬을 `<모드> <나머지 인자> --here`로 불러 그 절차를 따른다", "질문과 승인 요청(계획은 전문)은 턴의 마지막 메시지에 빠짐없이 쓰고 멈춘다" 두 줄과, 이 대화에서 사용자가 말한 배경이나 정한 것(있을 때만)이다.
  5. 세션 링크를 알린다. 그 일은 이 세션에서 하지 않고, 이 세션이 지휘한다.
     - 하위 세션이 턴을 끝내면 질문·승인 요청은 빠짐없이 사용자에게 보여 주고 답을 사용자의 말 그대로 그 세션에 전한다. 결과(커밋, 바뀐 파일)는 직접 확인해 사용자가 묻기 전에 보고한다.
     - 사용자가 하위 세션에서 직접 답했으면 그것을 받아들인다.

## 3. 프로젝트 설정

프로젝트 CLAUDE.md 에서 읽는다. 없으면 괄호 안의 기본값을 쓰고, 검증 명령이 없으면 묻는다.

- 기준 브랜치 (`main`)
- 검증 명령 (예: `pnpm verify` — 린트, 타입, 테스트, 빌드)
- 항목·보고에 쓸 언어 (대화의 언어)
- 웹 포트, 서버 포트 (없음): 적은 것만 항목마다 `기준 포트 + 항목 번호`로 나눈다

프로젝트 CLAUDE.md 의 규칙이 이 스킬과 superpowers 보다 우선한다.

## 4. 일하는 원칙

- 모르는 것은 가정하지 말고 말한다. 코드와 문서로 답할 수 있는 것은 묻지 않는다.
- 항목이 요구하는 것만 한다. 바뀐 줄은 모두 항목으로 거슬러 올라갈 수 있어야 한다.
- "됐다"고 하기 전에 검증을 새로 돌리고 그 결과를 보여 준다.
