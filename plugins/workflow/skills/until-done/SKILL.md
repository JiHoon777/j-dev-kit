# until-done

인자: `$ARGUMENTS`

이 세션은 맡겨진 상태다. 목표와 끝나는 조건만 받았고, 끝날 때까지 사용자에게 묻지 않고 진행한다. 프로젝트 CLAUDE.md 의 규칙은 이 스킬보다 우선한다. 권한 모드는 바꾸지 않는다(도구 권한 확인은 그대로 뜬다).

## 1. 시작

1. 인자에서 목표와 끝나는 조건을 읽는다. 끝나는 조건이 없으면 그것 하나만 묻는다. 그 밖의 것(고정할 것, 안 할 것, 순서)은 묻지 않는다.
2. 끝나는 조건을 어떻게 확인할지 정한다. 명령으로 확인할 수 있으면 그 명령, 아니면 기준마다 통과/실패를 가를 수 있는 확인 목록이다. 확인할 방법이 없는 조건이면 시작 전에 그렇다고 말한다.
3. 묻지 않고 한 번 알린다: 목표, 끝나는 조건, 확인 방법, 그리고 끝까지 이어 가게 하려면 사용자가 입력할 한 줄.

   ```
   /goal <끝나는 조건>. 대화에 보인 확인 결과가 모두 통과면 끝, 같은 실패가 세 번이면 멈춤
   ```

   `/goal`은 Claude Code 내장 명령이다. 매 턴 끝에 작은 모델이 조건을 판정하고, 아니면 이어 가게 한다. 그 모델은 대화만 보므로 3절의 확인 결과를 대화에 그대로 보여 준다.

## 2. 일하는 법

- j-dev-kit 의 `/task`, `/lead`, `/ui`, `/arch`는 사용자만 부를 수 있다. 필요한 스킬의 SKILL.md 와 절차 파일을 Read 로 읽고 그대로 따른다.

  | 스킬 | 찾는 곳 |
  | --- | --- |
  | `/task`, `/lead` | `${CLAUDE_SKILL_DIR}/../task/`, `${CLAUDE_SKILL_DIR}/../lead/` |
  | `/ui` | 설치본: `${CLAUDE_SKILL_DIR}/../../../../design/<버전>/skills/ui/` (버전이 여럿이면 가장 높은 것). 저장소에서 바로 쓰면 `${CLAUDE_SKILL_DIR}/../../../design/skills/ui/` |
  | `/arch` | 같은 방식으로 `architecture/…/skills/arch/` |

  이렇게 읽은 파일 안의 `${CLAUDE_SKILL_DIR}`는 그 스킬의 폴더(예: `/task`면 `${CLAUDE_SKILL_DIR}/../task`)를, `$ARGUMENTS`는 목표에 맞춰 정한 모드와 인자(예: `start 004`)를 뜻한다. 찾지 못하면 그 일은 하지 않고 5절의 보고에 적는다.
- 절차가 사용자에게 묻거나 승인을 받으라는 곳(질문, 계획 승인, 리뷰 지적 결정, 머지 승인, 시안 개수·방향·고르기 등)에서는 묻지 않는다. 목표와 끝나는 조건에 가장 맞는 쪽을 정하고 한 줄 남긴 뒤 계속한다. 플랜 모드에도 들어가지 않는다.

  ```
  Ruling: <정한 것> — <이유> — <틀렸을 때 비용>
  ```

  항목을 작업 중이면 그 항목의 `Implementation Notes`에, 아니면 5절의 보고에 모은다.
- 사용자가 중간에 말한 것(예: "배포는 나중에")은 끝까지 지킨다. 목표 밖으로 일을 넓히지 않는다.

## 3. 끝났는지 확인

직접 "됐다"고 판단하지 않는다. 일을 한 바퀴 마칠 때마다 확인한다.

- 명령이면 새로 돌린다.
- 확인 목록이면 Agent 도구로 새 에이전트를 띄운다. 끝나는 조건, 확인 목록, 볼 파일만 주고 기준마다 통과/실패와 근거를 받는다. 이 대화와 내 판단은 넘기지 않는다.

결과는 기준마다 `통과`/`실패`와 근거 한 줄로 대화에 그대로 보여 준다. 실패가 남으면 그것을 다음 일로 삼아 계속한다. 같은 실패가 세 번 되풀이되면 멈추고 5절의 보고를 한다.

## 4. 멈추고 묻는 것

되돌릴 수 없는 일만 묻는다.

- 지우기·버리기: 파일, 머지되지 않은 브랜치·워크트리, 커밋하지 않은 변경. 기준 브랜치에 머지된 브랜치와 워크트리는 커밋이 남으므로 묻지 않고 지운다
- 바깥에 보이는 일: 푸시, PR, 배포, 메시지 보내기
- 프로젝트 밖을 바꾸는 일: 전역 설치, 다른 저장소, 원격 DB·서비스
- 사용자만 아는 값

모아서 한 번에 묻는다. 목표에 들어 있거나 사용자가 이미 시킨 일(예: 목표가 "원격에도 올리기"면 푸시)과 이미 답한 것은 묻지 않는다.

## 5. 끝

끝나는 조건이 모두 통과했거나, 사용자가 "그만"이라고 했거나, 같은 실패가 세 번이면 보고하고 맡겨진 상태를 끝낸다.

- 한 일
- 스스로 정한 것: `Ruling:` 줄 전부
- 못 한 것과 이유, 확인하지 못한 것
- `/goal`이 아직 걸려 있으면 `/goal clear`로 끈다고 알린다
