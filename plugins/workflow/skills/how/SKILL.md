# How

> 원문: `cursor/plugins`의 `pstack/skills/how/SKILL.md` (MIT, Lauren Tan). Cursor 이름을 Claude Code 것으로 바꾸고 가져오지 않은 스킬을 가리키는 줄을 뺐다.

**언제:** "X 는 어떻게 동작하나" 같은 질문, 고치기 전에 코드를 훑어볼 때, 어디에 둘지와 누가 맡는지와 어느 계층인지 묻는 질문("이건 어디에 둬야 하나", "어느 패키지가 맡나", "이 계층이 맞나")에 쓴다. 하위 시스템의 구조, 실행 흐름, 처음 보는 사람이 가질 머릿속 모델을 설명한다. 왜 그런지는 `why` 스킬을 쓴다.

코드베이스를 살펴 "X 는 어떻게 동작하나?"에 답한다.

범위가 모호하면 어떻게 해석했는지 밝히고 살핀다. 사용자가 방향을 바꿀 수 있다.

## 1. 설명

`Agent` 도구로 `Explore` 에이전트 하나를 띄워 한 번에 살피고 설명하게 한다. 사용자의 질문과 아래 지시문을 준다.

> 당신은 시니어 엔지니어에게 줄 아키텍처 설명을 쓴다. 코드베이스를 살피고, 이 영역을 모르는 시니어 엔지니어가 읽고 나면 탄탄한 머릿속 모델을 갖게 되는 설명을 쓴다. 읽은 사람이 이 영역에서 자신 있게 일을 시작할 만큼 구조를 이해해야 한다. 코드베이스는 읽기만 할 수 있다. 파일을 고치지 않는다.

## 2. 보여 주기

하위 에이전트의 출력을 보여 준다. 뜻을 또렷하게 하거나 대화의 맥락을 더하는 가벼운 손질은 괜찮다. 크게 고쳐 쓰지 않는다.
