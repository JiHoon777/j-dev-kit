# lead run: 작업 세션을 띄우고 지휘하기

제안을 사용자에게 올려 항목으로 만들고, 항목마다 작업 세션을 띄우고, 보고를 확인해 계획·머지 지점에서 사용자에게 올리고, 승인된 브랜치를 머지한다.

돌릴 항목: `run` 뒤의 번호들. 없으면 3단계에서 고른다.

## 1. 상태 읽기

- `docs/backlog/`의 항목(`README.md`와 `_`로 시작하는 파일은 항목이 아니다)과 각 항목의 `status`, `dependencies`
- `docs/backlog/_proposals.md`(없으면 건너뛴다)
- "현재 상태"의 작업 브랜치와 워크트리: 이미 돌고 있거나 멈춰 있는 작업

기준 브랜치가 아니거나 커밋하지 않은 변경(제안함 파일은 뺀다)이 있으면 멈추고 알린다.

## 2. 제안 승격

제안함에 제안이 있으면 한 번에 보여 주고 묻는다: 승격 / 기각 / 그대로 둠.

- **승격:** `${CLAUDE_SKILL_DIR}/../task/references/create.md`를 읽고 그 2~4단계대로 항목을 만든다. 제안함에서 그 줄을 지운다.
- **기각:** 제안함의 `## 기각`에 제목, 날짜, 이유를 적고 원래 줄을 지운다.
- 사용자가 승격하지 않은 제안으로는 작업을 시작하지 않는다.

## 3. 나누기

- 후보: `status: To Do`이고 `dependencies`가 모두 `docs/done/`에 있는 항목. `In Progress`인데 돌고 있는 세션이 없는 항목은 이어 갈지 묻는다.
- 한 번에 "동시 작업 세션" 수까지 고른다. 무엇을 함께 돌릴지는 직접 판단한다. 같은 곳을 고치는 항목을 함께 돌려도 된다. 충돌은 6단계에서 푼다.
- 고른 항목을 번호와 제목으로 한 줄씩 보여 주고 바로 시작한다.

## 4. 작업 세션 띄우기

항목 하나에 세션 하나. 기준 브랜치에서 갈라진 자기 워크트리에서 돌게 한다.

- 세션을 새로 시작하는 도구가 있으면 그것을 쓴다(사용자가 열어 보고 직접 말할 수 있다).
- 없으면 워크트리로 격리한 백그라운드 서브에이전트를 쓴다.

작업 세션은 이 대화를 볼 수 없으니 지시문에 넣는다:

1. 항목 파일 경로, 기준 브랜치, 검증 명령, 문서 언어.
2. `${CLAUDE_SKILL_DIR}/../task/references/start.md`의 절대 경로. 이 파일을 끝까지 읽고 따르되 아래가 우선한다.
3. 이 세션은 기준 브랜치에서 막 갈라진 자기 워크트리다. start 1단계의 브랜치 확인은 건너뛴다. 다른 `w/` 브랜치는 다른 작업 세션의 것이니 건드리지 않는다.
4. **계획:** 플랜 모드를 쓰지 않는다. 계획을 보고하고 멈춘다. 승인 메시지를 받으면 start 4단계부터 한다.
5. **구현 뒤:** 같은 폴더의 `end.md` 1~6단계를 한다. 4단계는 묻지 않는다. 🔴 는 고치고, 🟡 는 고치지 않고 보고에 적는다. 7단계(머지)는 하지 않는다. 푸시하지 않는다.
6. 백로그 항목을 새로 만들지 않는다. 필요해 보이는 다른 일은 보고에 적는다.
7. 모르는 것, 범위가 커지는 것, 기준선에 없던 실패를 고치지 못하는 것은 보고하고 멈춘다.
8. **보고 형식:** 첫 줄에 상태(`계획 승인 대기` / `질문` / `막힘` / `머지 준비`)와 항목 번호. 이어서 브랜치 이름, 한 일이나 계획 몇 줄, 남긴 🟡, 확인하지 못한 것.

## 5. 보고를 확인하고 올리기

보고는 그 세션의 주장이다. 올리기 전에 직접 본다.

| 상태 | 확인할 것 | 사용자에게 |
| --- | --- | --- |
| 계획 승인 대기 | 계획이 항목의 Acceptance Criteria 를 다 덮고 그 밖의 일을 넣지 않았는지 | 계획 요약, 승인 / 고칠 점 |
| 질문·막힘 | 코드와 문서로 답할 수 있으면 직접 답해 돌려보낸다 | 답할 수 없는 것만, 바로 |
| 머지 준비 | `git diff --stat <기준>...<브랜치>`, 항목 파일의 AC·DoD 체크와 `Final Summary`, 검증 결과 | 6단계 |

- 같은 때 온 계획과 머지 준비는 묶어서 한 번에 올린다. 질문과 막힘은 기다리지 않고 올린다.
- 사용자의 답은 그 말을 그대로 인용해 해당 세션에 전한다. 답이 없으면 기다린다.
- 보고가 실제와 다르면 사용자에게 올리지 않고 무엇이 다른지 적어 돌려보낸다.

## 6. 머지 (한 번에 하나)

머지 준비가 된 브랜치를 보여 주고 묻는다: 바뀐 것, 남은 🟡(지금 고침 / 새 항목 / 그대로), 머지할지.

1. 사용자가 승인한 브랜치만, 하나씩 기준 브랜치에 머지한다. 프로젝트 CLAUDE.md 의 PR·푸시 규칙이 있으면 따른다. 푸시는 요청할 때만.
2. 충돌이 나면 두 항목의 의도를 보고 푼다. 어느 쪽을 살릴지 판단할 수 없으면 멈추고 묻는다.
3. 머지할 때마다 검증 명령을 새로 돌린다. 실패하면 다음 머지를 멈추고 알린다. 스스로 되돌리지 않는다.
4. "지금 고침"은 그 작업 세션에 돌려보낸다. "새 항목"은 2단계처럼 만든다.
5. 머지한 항목의 작업 세션과 워크트리를 정리하자고 제안한다.

## 7. 다음

- 자리가 났고 후보가 남았으면 3단계로 돌아간다.
- 작업 세션이 보고한 "다른 일"은 다음 2단계에서 제안과 함께 보여 준다.
- 끝나면 보고한다: 머지한 항목, 승인을 기다리는 것, 멈춘 것, 남은 `To Do` 항목.
