# lead scout: 제안함 갱신하기

저장소를 읽고 `docs/backlog/_proposals.md` 파일 하나를 새로 쓴다. 제안만 한다. 제안이 백로그 항목이 되는 것은 사용자가 `/lead run`에서 승격할 때뿐이다.

## 1. 지킬 것

- 쓰는 파일은 `docs/backlog/_proposals.md` 하나다. 코드, 백로그 항목, 다른 문서는 고치지 않는다. 커밋하지 않는다.
- 읽기만 한다: 파일 읽기, `git log`, `git diff`. 검증 명령, 빌드, 서버는 돌리지 않는다.
- `docs/backlog/`가 없으면 폴더만 만들고 `_proposals.md`를 쓴다. `README.md`와 `_template.md`는 `/task create`가 만든다.
- 백로그 항목이 없어도 제안한다. 그때 "백로그 정리"는 "없음"이다.
- 언어는 프로젝트 CLAUDE.md 의 문서 언어를 따른다.

## 2. 읽을 것

없는 것은 건너뛴다.

- `docs/backlog/`와 `docs/done/`의 항목, `docs/backlog/README.md`의 메모
- 기존 `docs/backlog/_proposals.md`: `## 기각` 아래와 지난 제안
- README, CLAUDE.md, 지난 실행 뒤의 커밋(`_proposals.md`의 "본 커밋" 다음부터. 처음이면 최근 30개)

## 3. 세 관점으로 제안 찾기

| 관점 | 찾는 것 |
| --- | --- |
| 아이디어 | 문서에 적힌 목표 중 항목이 없는 것, 메모 중 항목으로 만들 만한 것, 끝난 항목의 `Final Summary`에 "미룬 것"으로 남은 것 |
| 백로그 정리 | 겹치는 항목, 코드에 이미 반영된 항목, 한 번에 리뷰하기 큰 항목, 틀린 `dependencies` |
| 개선 | `TODO`·`FIXME`, 최근 커밋에서 같은 곳을 되풀이해 고친 흔적, 끝난 항목의 `Implementation Notes`에 적힌 문제 |

- 관점마다 최대 3개. 못 찾으면 "없음"이라고 쓴다. 채우려고 지어내지 않는다.
- 제안마다 근거를 단다: `파일:줄`, 커밋 해시, 항목 번호 중 하나. 근거를 댈 수 없으면 제안하지 않는다.
- `docs/backlog/`·`docs/done/`의 항목과 겹치거나 `## 기각`에 있는 것은 제안하지 않는다.
- 지난 제안은 지금도 맞는 것만 남긴다. 파일은 통째로 새로 쓴다(`## 기각`만 그대로 옮긴다).

## 4. 파일 형식

```markdown
# 제안함

갱신: YYYY-MM-DD HH:MM · 본 커밋: <해시>

## 아이디어

- **<제목>** — <왜 필요한가 한 문장> (근거: `src/a.ts:12`) · 다음: 분명함
- **<제목>** — … (근거: 항목 004) · 다음: 논의 필요

## 백로그 정리

없음

## 개선

- …

## 기각

- <제목> — YYYY-MM-DD — <이유>
```

"다음: 분명함"은 바로 항목으로 만들 수 있는 것, "논의 필요"는 사용자가 방향을 정해야 하는 것이다. `## 기각`은 `/lead run`이 적는다.

## 5. 보고

한두 줄로 끝낸다: 관점별 제안 수와 이번에 새로 생긴 제안의 제목. 새 제안이 없으면 "새 제안 없음".
