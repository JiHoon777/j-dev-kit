# lead schedule: scout 을 주기 실행으로 걸기

주기: `schedule` 뒤의 인자. 없으면 묻는다(예: 평일 아침 9시).

## 1. 제안함을 git 에서 빼기

`.gitignore`에 `docs/backlog/_proposals.md`가 없으면 추가하자고 제안하고, 승인을 받아 추가하고 커밋한다: `chore: ignore backlog proposals`. 제안함은 실행마다 바뀌는 파일이라 커밋하지 않는다. 빼 두지 않으면 `/task start`가 "커밋하지 않은 변경"에서 멈춘다.

## 2. 등록

지금 쓸 수 있는 예약 수단 가운데 위에서부터 고른다.

| 수단 | 특징 |
| --- | --- |
| 앱의 예약 작업 도구 | 앱이 열려 있을 때 돈다. 실행마다 새 세션이고, 끝나면 이 세션에 알림이 온다 |
| `/loop` | 이 세션이 열려 있을 때만 돈다. 7일 뒤 만료된다 |

예약 실행은 이 대화를 모른다. 프롬프트에 넣는다:

1. 저장소의 절대 경로와 "이 폴더에서 일한다"는 말.
2. "아래 scout 절차를 따른다. 사용자가 없는 예약 실행이니 4단계에서 묻지 않는다."와 `${CLAUDE_SKILL_DIR}/references/scout.md`의 전문.
3. "`workflow:backlog-scout` 에이전트를 쓸 수 없으면 아래 절차를 직접 따른다."와 `${CLAUDE_SKILL_DIR}/../../agents/backlog-scout.md`의 본문 전문.

- 같은 일을 하는 예약이 이미 있으면 새로 만들지 않고 그것을 고친다.
- 등록이 권한 때문에 막히면 우회하지 않는다. 넣을 프롬프트와 주기를 보여 주고 사용자가 앱에서 직접 만들게 한다.

## 3. 알리기

- 주기, 다음 실행 시각, 어떤 수단으로 걸었는지
- 그 수단의 한계(앱이나 세션이 닫혀 있으면 돌지 않는다)
- 프롬프트에 붙여 넣은 절차는 플러그인을 업데이트해도 바뀌지 않는다. 새 절차로 돌리려면 `/lead schedule`을 다시 부른다
- 실행마다 이 세션에 알림이 오고, 그때 제안을 올린다(`scout.md` 4단계). 이 세션이 닫혀 있었으면 제안은 `/lead run`에서 본다
