# lead schedule: scout 을 이 세션에서 주기로 부르기

주기: `schedule` 뒤의 인자. 없으면 묻는다(예: 평일 아침 9시). 인자가 `끄기`나 `off`면 3절만 한다.

예약은 이 세션 안에서만 돈다. 정한 시각이 되면 이 세션이 scout 절차(`scout.md`)를 따라, 에이전트를 띄우고 보고를 받아 제안함에 적고 새로 생긴 제안의 승격을 묻는다. 따로 세션을 만드는 예약(앱의 예약 작업)은 쓰지 않는다. 그 세션은 따라가 볼 수 없고 보고가 이 세션으로 오지 않는다.

## 1. 제안함을 git 에서 빼기

`.gitignore`에 `docs/backlog/_proposals.md`가 없으면 추가하자고 제안하고, 승인을 받아 추가하고 커밋한다: `chore: ignore backlog proposals`. 제안함은 실행마다 바뀌는 파일이라 커밋하지 않는다. 빼 두지 않으면 `/task start`가 "커밋하지 않은 변경"에서 멈춘다.

## 2. 등록

세션 안 예약 도구(CronCreate, `/loop`가 쓰는 것)로 건다.

- 프롬프트는 슬래시 명령이 아니라 지시문으로 쓴다. 예약으로 들어온 `/workflow:lead scout`는 스킬로 펼쳐지지 않고 글로만 들어온다. 프롬프트에 넣는다:
  1. "lead scout 예약 실행이다. `<스킬 폴더>/references/scout.md`를 Read 도구로 끝까지 읽고 그대로 따른다."
  2. "그 파일에 적힌 `${CLAUDE_SKILL_DIR}`는 `<스킬 폴더>`를 뜻한다."
  3. "에이전트 이름은 `workflow:backlog-scout`와 `workflow:trend-scout`다."
  4. "4단계(올리기)에서는 이번에 새로 생긴 제안만 보여 주고 묻는다. 쌓인 전체는 `/lead run`에서 본다. 새로 생긴 제안이 없으면 승격은 묻지 않고, 그렇다는 것과 4단계에서 덧붙일 줄(뺀 것, 틀린 것, 읽지 못한 것)만 알린다."

  `<스킬 폴더>`는 이 스킬의 절대 경로(Base directory)로 바꿔 넣는다. 절차는 붙여 넣지 않는다.
- 경로에 플러그인 버전이 들어간다. 플러그인을 업데이트하면 `/lead schedule`을 다시 불러 새 경로로 건다.
- 주기를 cron 으로 바꾼다. 사용자가 정확한 시각을 말하지 않았으면 정각과 30분은 피한다.
- 끝이 있으면("오늘 5시까지") 날짜와 시간대를 cron 에 고정해 그 뒤로는 돌지 않게 한다.
- 프롬프트가 "lead scout 예약 실행"으로 시작하는 예약이 이미 있으면(CronList) 지우고 새로 건다. 경로의 버전이 달라도 같은 예약이다.
- "지금부터"처럼 바로 시작하라고 했으면 등록한 뒤 `${CLAUDE_SKILL_DIR}/references/scout.md`를 읽고 한 번 따른다.
- 이 세션에 세션 안 예약 도구가 없으면 등록하지 않는다. 주기와 위 지시문을 보여 주고 `/loop`로 직접 걸라고 알린다.

## 3. 끄기

CronList 에서 프롬프트가 "lead scout 예약 실행"으로 시작하는 예약을 찾아 CronDelete 로 지운다. 없으면 없다고 알린다.

## 4. 알리기

- 주기, 다음 실행 시각(등록 결과에 나온 시각)
- 한계: 이 세션이 열려 있고 쉬고 있을 때만 돈다. 정한 시각보다 늦게 돌 수 있다. 7일 뒤 만료된다
- 바깥 동향이 켜져 있으면(기본) 실행마다 웹을 검색하고 읽는다. 끄려면 CLAUDE.md 에 `바깥 동향: 끄기`
- 끄려면 `/lead schedule 끄기`(또는 `off`)
