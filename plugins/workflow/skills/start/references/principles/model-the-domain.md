# Model the Domain

> 원문: `cursor/plugins`의 `pstack/skills/principle-model-the-domain/SKILL.md` (MIT, Lauren Tan). Cursor 이름을 Claude Code 것으로 바꾸고 가져오지 않은 스킬을 가리키는 줄을 뺐다.

**언제:** 상태가 있는 로직을 쓸 때, 또는 코드에 분기가 많거나 같은 모양 가정이 여러 파일에 되풀이될 때.

도메인을 조건문에 흩어 놓지 말고 자료 구조에 담는다. 맞는 구조는 잘못된 상태를 표현할 수 없게 하고 분기를 없앤다.

흩어진 boolean 이나 단계 검사 대신 상태 기계를, 느슨한 매개변수 대신 타입이 있는 모델을, 여러 파일에 퍼진 분기 대신 map, 레지스트리, discriminated union 을, 그때그때 하는 변경 대신 reducer 를 쓴다. 접근 패턴이 요구하는 곳에는 인덱스, 큐, 정규화한 컬렉션을 쓴다.

억지로 하지 않는다. 모양이 분명하고 한곳에 머물고 커질 것 같지 않으면 지루한 코드를 그대로 둔다. 분기나 잘못된 상태를 없애지 못하면서 간접 참조만 더하는 추상화는 믿지 않는다.

이것을 건너뛴 신호: 기능 하나가 if/else 사슬에 분기를 하나 더 늘린다. 또는 첫 번째와 늘 맞아야 하는 두 번째 boolean 이 생긴다.
