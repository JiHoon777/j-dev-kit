# Build the Lever

> 원문: `cursor/plugins`의 `pstack/skills/principle-build-the-lever/SKILL.md` (MIT, Lauren Tan). Cursor 이름을 Claude Code 것으로 바꾸고 가져오지 않은 스킬을 가리키는 줄을 뺐다.

**언제:** 사소하지 않은 모든 일. 대량 작업만이 아니라 수정, 마이그레이션, 분석, 검사에 다 해당한다. 만든 도구는 리뷰어가 다시 돌려 볼 수 있는 산출물이다.

일이 사소하지 않으면 손으로 하지 말고 그 일을 하는 도구(codemod, 스크립트, 생성기, 다시 돌릴 수 있는 검사)를 만든다. 기준은 반복 여부가 아니라 사소한지다. 뻔한 수정 두어 개일 때만 도구를 건너뛴다.

- 첫 단위는 손으로 한다. 그다음 도구를 만들고, 그 단위에 다시 돌려 도구가 맞는지 증명한다. 다시 돌려도 안전하게 만든다.
- 결정적인 도구가 여러 에이전트에 나눠 맡기는 것(fan-out)보다 낫다. 나눠 맡길 때는 절차, 검증 계약, 넘지 말아야 할 선을 스킬 하나로 쓴다. 맡은 쪽은 그 스킬을 읽기만 하고 고칠 수 없다.
- 이 원칙을 적용하면 파일이 생긴다. diff 에 스크립트, codemod, 생성기, 맡은 쪽이 읽는 스킬 중 어느 것도 없으면 적용하지 않은 것이다. 일이 세션보다 오래 가면 커밋한다.
- 그 일을 하거나 증명하는 가장 작은 스크립트를 만든다. 프레임워크는 만들지 않는다.
