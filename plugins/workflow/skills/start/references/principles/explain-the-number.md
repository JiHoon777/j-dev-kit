# Explain the Number

> 원문: `cursor/plugins`의 `pstack/skills/principle-explain-the-number/SKILL.md` (MIT, Lauren Tan). Cursor 이름을 Claude Code 것으로 바꾸고 가져오지 않은 스킬을 가리키는 줄을 뺐다.

**언제:** 재기 전에, 그리고 잰 숫자(속도 향상, 회귀, 처리량, 지연 시간, eval 결과)를 믿거나 보고하거나 그 숫자로 움직이기 전에. 무엇이 그 숫자를 제한하는지 찾고, 생각한 일이 아닌 다른 것을 잰 것은 아닌지 배제한다.

- **돌리기 전에 결정을 적는다.** 어떤 결과가 나오면 그 결정이 바뀌는지, 잡음 바닥(noise floor)이 얼마인지 적는다. 실행 간 편차가 효과보다 크면 멈춘다.
- **"왜 두 배가 아닌가?"를 묻는다.** 결과를 묶어 두는 자원이나 코드 경로를, 실행 중에 뜬 프로파일이나 카운터로 짚는다. 코드를 읽고 한 추측은 제한 요인이 아니다.
- **그 숫자가 재고 있을 수 있는 다른 것을 적는다**(오류, 건너뛰었거나 캐시된 작업, 실행된 적 없는 코드, 튜닝하지 않은 한쪽, 잡음, 의미를 갖기에는 너무 작은 조각). 하나씩 증거로 배제한다.
- **실행 횟수, 편차, 제한 요인을 숫자와 함께 둔다.**

성능 숫자라면 `skills/benchmark-checklist.md`를 따른다. eval 결과라면 모든 실행이 과제를 수행했는지, 차이가 여러 시도와 모델에 걸쳐 유지되는지, 그 시나리오가 중요한지 묻는다.
