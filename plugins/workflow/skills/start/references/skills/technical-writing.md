# Technical writing

> 원문: `cursor/plugins`의 `pstack/skills/technical-writing/SKILL.md` (MIT, Lauren Tan). Cursor 이름을 Claude Code 것으로 바꾸고 가져오지 않은 스킬을 가리키는 줄을 뺐다.

**언제:** 문서, RFC, readme, PR 설명, 커밋 메시지를 쓰거나 리뷰할 때 쓴다. 층으로 쌓은 글쓰기 기준이다: Diátaxis 구조, Google developer style 문장, STE 지시 규칙, Global English 문법.

지친 엔지니어가 한 번 읽고 알아듣게 쓴다.

영어 문법에만 해당하는 규칙은 "영어로 쓸 때"라고 밝혀 두었다. 나머지 규칙은 한국어 글에도 그대로 적용한다.

- 일을 하지 않는 낱말은 모두 지운다.
- 짧고 흔한 낱말을 쓴다. 영어 예: "utilize"가 아니라 "use".
- 규칙을 따랐더니 문장이 나빠지면 문장을 다른 방법으로 고치거나 그대로 둔다.
- 실제 심볼, 파일, 플래그, 명령 이름을 쓴다. 비슷한 말이나 풀이로 바꿔 쓰지 않는다.
- 전문 용어를 지어내지 않는다. 개발자가 소리 내어 말할 낱말을 쓴다. 이름 붙은 패턴은 처음 나올 때 뜻을 말한다.

## 리듬에 변화를 준다

- 문장 길이를 섞는다. 생각 둘을 담은 문장은 나눈다. 생각 하나를 담은 긴 문장은 그대로 둔다.
- explanation 에서는 관점을 갖는다. reference 는 건조하게 둔다.
- 구체적으로 쓴다. "스키마 변경은 문제를 일으킬 수 있다"가 아니라 "컬럼 이름을 바꾸면 빌드가 실패한다"라고 쓴다.

## 먼저 모드를 고른다 (Diátaxis)

문서 하나에 모드 하나다. 모드를 섞지 않는다. 섞이면 나누고 링크한다.

- **Tutorial: 해 보면서 배우기.** 배우는 사람이 무엇을 만들지 말한다. 단계마다 눈에 보이는 결과가 나오고, 무엇이 보여야 하는지 말한다. 설명은 한 구절과 링크로 끝낸다.
- **How-to: 목표까지 가는 단계.** 독자의 문제를 푼다. 독자가 할 줄 안다고 본다. 행동만 쓴다. 갈림길을 허용한다. 가이드 이름은 하는 일로 짓는다.
- **Reference: 찾아보는 사실.** 묘사만 한다. 건조하고, 빠짐없고, 확실하게 쓴다. 묘사하는 대상의 구조를 그대로 따른다.
- **Explanation: 이해와 까닭.** 경계가 있는 주제 하나를 다룬다. 맥락을 준다: 설계 결정, 역사, 제약, 대안. 의견은 여기서만 허용한다.

## 독자에게 말하는 문장을 쓴다 (Google developer style)

- 독자에게 직접, 현재형으로 말한다. 영어로 쓸 때는 독자를 "you"로 부른다.
- 누가 무엇을 하는지 말한다. 수동태는 행위자를 모르거나 행위자가 중요하지 않을 때만 쓴다.
- 지시는 명령문으로 쓴다. 조건을 지시보다 앞에 두고, 흔한 경우를 먼저 둔다.
- 유행어와 비유를 쓰지 않는다. 영어로 쓸 때는 "please"를 쓰지 않는다. 절차에는 "simply", "easy", "quickly"(간단히, 쉽게, 빠르게)를 절대 쓰지 않는다.
- 무엇을 말할지 미리 예고하지 않는다. 잇따른 문장을 같은 구절로 시작하지 않는다.
- 링크에는 어디로 가는지 알려 주는 말을 쓴다.
- 제목에 요점을 담는다. 영어로 쓸 때는 제목을 sentence case 로 쓴다. 한 쪽에 h1 은 하나다. 제목 단계를 건너뛰지 않는다.
- 순서가 있으면 번호 목록을 쓰고, 나머지는 모두 글머리표를 쓴다. 목록은 온전한 문장으로 소개한다. 항목의 모양을 서로 맞춘다.
- 코드는 코드 글꼴로 쓴다. UI 요소는 굵게 쓴다. 영어로 쓸 때는 serial comma 를 쓴다. "etc."(등)는 뺀다.

## 한 번에 하나씩 읽히게 쓴다 (STE 규칙)

- 지시는 한 문장에 하나다. 그 밖의 글은 한 문장에 한 생각이다.
- 지시문은 약 20 낱말, 그 밖의 문장은 약 25 낱말을 넘으면 나눈다. 이 수는 영어 낱말 기준이다.
- 경고나 조건은 그것이 지키는 단계보다 앞에 둔다.
- 영어로 쓸 때는 "the"와 "a"를 빼지 않는다.
- 낱말 하나에 뜻 하나를 주고, 동작 하나에 낱말 하나를 고른다.
- 절차는 직접 명령문으로 쓴다. 이야기하듯 쓰지 않고 수동태로 쓰지 않는다.
- 영어로 쓸 때는 "-ing" 낱말을 되도록 피한다.

## 두 가지로 읽히는 문장을 남기지 않는다 (Global English)

- "only"나 "not"처럼 뜻을 한정하거나 뒤집는 말은 그 말이 바꾸는 낱말 바로 옆에 둔다.
- 길게 늘어선 명사는 끊는다.
- "it", "they", "this"(그것, 그들, 이것) 같은 지시어는 모두 뚜렷한 대상 하나를 가리키게 한다. "this"나 "which"(이는, 이것은)로 절 전체를 가리키지 않는다.
- 서술어를 빼지 않는다. 영어로 쓸 때는 "that"처럼 구조를 보여 주는 작은 낱말도 빼지 않는다.
- 영어로 쓸 때는 잘못 읽힐 수 있으면 나열한 항목마다 관사를 되풀이한다. "and"나 "or"(와, 또는)가 어느 부분을 잇는지 밝힌다.
- 세미콜론이나 줄표가 아니라 마침표를 쓴다. 빗금을 쓰지 않는다. 영어로 쓸 때는 "(s)"를 쓰지 않는다. 괄호 안의 글은 문법적으로 온전한 단위로 만든다.
- 한 가지를 어디서나 한 이름으로 부른다.
- 관용구, 구어 표현, 라틴어 약어, 은유를 쓰지 않는다.

## 문체와 저장소에 맞출 것

- 이 스킬로 손대는 문서에는 모두 `skills/unslop.md`를 적용한다. slop 패턴 목록은 그 파일이 맡는다: AI 낱말, 군말, 얼버무리는 말, 서식에서 드러나는 티.
- PR 설명과 커밋 메시지도 글이다. Diátaxis 를 뺀 모든 층을 적용한다. PR 본문은 리뷰어가 1분 안에 읽는 브리핑이다. 하위 에이전트 로그, SHA 목록, 지표 표를 붙여 넣지 않는다. 링크한다.
- 제품 UI 문자열은 문서가 아니다. 그 문자열에는 제품의 문구 지침을 쓴다.
- 코드 조각은 탭으로 들여쓴다. 실제 경로를 쓴다. 개수나 트리에 관한 주장은 그 주장을 넣는 커밋에서 참이어야 하고, 그것을 다시 만드는 명령을 함께 적는다.
