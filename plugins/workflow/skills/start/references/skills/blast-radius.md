# Blast radius

> 원문: `cursor/plugins`의 `pstack/skills/blast-radius/SKILL.md` (MIT, Lauren Tan). Cursor 이름을 Claude Code 것으로 바꾸고 가져오지 않은 스킬을 가리키는 줄을 뺐다.

**언제:** 변경을 내보내기 전에 diff 바깥에서 무엇이 깨질 수 있는지 찾을 때 쓴다. "X 의 blast radius", "이게 뭘 깨뜨릴 수 있나" 같은 요청이나, 작지만 믿기지 않는 diff 를 리뷰할 때다.

변경이 다른 곳에서 무엇을 깨뜨리는지 내보내기 전에 찾는다. "X 의 blast radius", "이게 뭘 깨뜨릴 수 있나" 같은 요청이나, 작지만 아직 믿기지 않는 diff 를 리뷰할 때 쓴다.

`skills/how.md`, `skills/why.md`와 짝이다. `skills/how.md`는 코드가 무엇을 하는지 알려 준다. `skills/why.md`는 코드가 왜 그런 모양인지 알려 준다. Blast radius 는 코드가 다른 곳에서 무엇을 깨뜨리는지 알려 준다.

호출하는 곳을 나열하는 것은 이 일이 아니다. 그것은 에이전트가 grep 으로 금방 찾는다. 이 일은 grep 으로 보이지 않는 고장을 찾는 것이다.

## 자기가 쓴 글을 믿지 않는다

그럴듯하게 들리는 blast-radius 글은 쓸모가 없다. 맞든 틀리든 설득력 있게 읽히기 때문이다. 그러니 글을 그대로 넘기지 않는다. 전체가 기대는 사실 한두 개를 찾아 코드를 돌려 증명한다.

### 얼마나 확실한가

변경의 안전이 기대는 사실마다, 싸게 갈 수 있는 데까지 아래 목록을 내려가고 어디서 멈췄는지 말한다.

1. 그렇다고 말했다. 이것만으로는 쓸모없다.
2. 줄을 짚었다. 실제 `file:line`이나 라이브러리의 소스다.
3. 나쁜 경우가 일어날 수 없음을 보였다. 실패 과정을 한 단계씩 따라갔고 거기에 닿지 않는다.
4. 돌려 봤다. 실제 코드를 부르고, 틀리면 요란하게 실패하는 스크립트나 테스트다.
5. 실행 중인 앱에서 재현했다.

4번은 대개 작은 스크립트 하나다. 앱이 싣는 것과 같은 라이브러리를 import 하고, 걱정되는 바로 그 함수를 부른다.

## 단계

1. 변경을 읽는다. diff, 더하고 바꾸고 지운 심볼, 이제 달라진 동작을 본다. diff 가 드러내 말하지 않는 부분도 본다. PR 과 그 커밋을 가져온다.
2. 변경이 안전한 까닭인 사실 하나를 찾는다. 위험해 보이는 변경은 대부분 사실 하나 덕분에 안전하다. 예를 들면 "이 호출은 이미 죽은 캐시 항목만 버리고 다른 일은 하지 않는다"이다. 그 사실을 찾는다. 그 사실이 맞으면 위험한 경우 대부분이 한꺼번에 풀린다. 시간은 여기에 쓰고, '혹시 모를 것'을 길게 늘어놓는 데 쓰지 않는다.
3. grep 이 멈추는 곳을 본다. 부르는 라이브러리의 소스를 읽고, 고정된 버전과 로컬 패치를 확인한다. 언제 도는지 따진다: microtask, unmount 와 teardown, Solid 와 React 의 차이. 심볼 검색이 놓치는 것을 따라간다: API 가 돌려주는 JSON, DB 컬럼, wire format, 같은 바이트를 읽는 다른 언어, feature flag, 세 단계 아래에 있는 코드.
4. 위험마다 정직하게 적는다. 실제로 일어날 가능성과 일어났을 때의 비용을 적는다. 확인한 위험은 남긴다. 확인하고 걷어낸 위험은 따로 적는다. 실제 `file:line`을 댄다. 검색해서 아무것도 나오지 않은 것도 답이다. 호출하는 곳이나 API 를 지어내지 않는다.
5. 그 사실 하나를 증명한다. 실제 코드를 돌리는 스크립트나 테스트를 쓰고, 돌리고, 일어난 일을 붙여 넣는다.

## 돌려줄 것

- **무엇을 하나.** 무엇이 바뀌었는지 적는다. 뻔하지 않은 부분도 적는다.
- **안전한 까닭인 사실 하나.** 그 사실을 적고, 위 목록의 몇 번까지 갔는지 말하고, 증거를 보인다. 증명하지 못했으면 unproven 이라고 적는다.
- **위험.** 위험마다 어떻게 깨지는지, `file:line`, 얼마나 일어날 법하고 얼마나 나쁜지, 어떻게 확인하는지 적는다. 중요한 위험에는 증거를 붙여 넣는다.
- **걷어낸 것.** 무엇을 확인했고 왜 괜찮은지 적는다.
- **머지 전에.** 진짜 버그를 잡는 가장 싼 테스트나 재현 방법. 쓴 스크립트도 넣는다.

`skills/unslop.md`를 거쳐 쓰고, 실제 코드를 인용하고, 공개된 곳으로 나가기 전에 비공개 내용을 지운다.

**답:** 위의 글. 안전한 까닭인 사실 하나는 증명했거나 unproven 으로 표시한다.
