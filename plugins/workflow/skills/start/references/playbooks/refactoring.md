# Refactoring

> 원문: `cursor/plugins`의 `pstack/skills/poteto-mode/playbooks/refactoring.md` (MIT, Lauren Tan). Cursor 이름을 Claude Code 것으로 바꾸고 가져오지 않은 스킬을 가리키는 줄을 뺐다.

**언제:** 동작은 그대로 두고 구조만 바꾸는 항목. 한곳에 모인 변경에서 중간 크기 변경까지를 다룬다.

**계약의 주인은 나다. 구조는 바뀐다. 동작은 바뀌지 않는다.** 동작을 더하는 `start` 절차의 기본 흐름과 다르고, 동작을 바로잡는 `playbooks/bug-fix.md`와도 다르다.

정리하다가 빠진 기능이나 진짜 버그가 드러나면 따로 떼어 내고, 고정한 계약을 기준으로 구조 변경을 먼저 낸다. 재설계는 해도 된다. 다만 재설계라고 이름 붙이고 `start` 절차의 기본 흐름으로 보낸다. 이 플레이북은 한곳에 모인 변경에서 중간 크기 변경까지를 다룬다.

1. 동작 계약을 먼저 고정한다. 영향받는 하위 시스템을 추적해 계약을 파악한 다음, 구조를 하나라도 옮기기 전에 지금 동작을 담는 특성 테스트(characterization test), 스냅샷, 동등성 하네스 중 하나를 쓴다. 그 영역에 커버리지가 없으면 구조를 건드리기 전에 고정 장치부터 쓴다. 타입 검사와 린트는 고정 장치가 아니다.
2. 코드에 빠져 있는 구조를 `principles/model-the-domain.md`에 따라 이름 붙인다. 모양이 이미 분명하고 한곳에 모여 있으면 지루한 코드는 그대로 둔다. 모양을 바꾸면 분기나 잘못된 상태가 없어져야 한다. 간접 단계가 늘면 안 된다.
3. 목표 모양을 이름 붙인다. 오늘 새로 짓는다면 모듈 배치, 타입, 호출 그래프가 어때야 하는지 적는다(`principles/foundational-thinking.md`, `principles/redesign-from-first-principles.md`). 목표가 함수 경계를 넘으면 옮기기 전에 `skills/architect.md`로 모양을 잡는다.
4. 더하기 전에 뺀다. 새 모양을 들이기 전에 죽은 코드를 지우고, 호출자가 하나뿐인 래퍼를 합치고, 중복된 검증기를 빼고, 주인 없는 참조를 없앤다(`principles/subtract-before-you-add.md`). 목표 모양에 닿는 가장 작은 변경을 낸다(`principles/laziness-protocol.md`). "도움이 될지도 모르는" 추측성 정리는 되돌린다.
5. 동작을 지키는 작은 걸음으로 옮기고, 걸음마다 고정 장치가 통과하게 둔다. API 모양을 바꿀 때는 호출자를 모두 옮기고 옛 API 를 같은 차례에 지운다(`principles/migrate-callers-then-delete-legacy-apis.md`). 호환용 끼움 코드(shim)를 두지 않고, 옛 경로와 새 경로를 나란히 두지 않는다. 이름을 바꿀 때마다 실제 파일에서 확인한다. 이름 바꾸기는 문자열, 글, 역참조에 있는 쓰임을 소리 없이 놓친다. 기계적인 수정은 범위(파일 경로, 옮기는 이름, 지킬 동작)를 구체적으로 정해 하위 에이전트에 맡긴다.
6. 동작이 바뀌지 않았음을 "컴파일된다"가 아니라 실제 결과물로 증명한다(`principles/prove-it-works.md`). 모양을 크게 바꿨으면 동등성 검사를 돌린다. 옛 출력과 새 출력을 비교하는 스크립트, 기록해 둔 기준선을 새 코드에 다시 돌리기, 맞는 표면에서 `skills/control-ui.md`나 `skills/control-cli.md`로 하는 스모크 실행 중 하나다.
7. 남길 만한 변경인지 확인한다. 성공의 척도는 읽는 사람의 부담이 줄었는가다(`principles/minimize-reader-load.md`). diff 가 어디에서도 읽는 부담을 줄이지 않으면 되돌린다.
8. 작고 순서 있는 커밋으로 리베이스한다. 빼는 커밋, 그다음 모양 바꾸기, 그다음 뒤따르는 정리 순이다. `principles/sequence-verifiable-units.md`로 커밋 모양을 잡아, 동작을 지키는 조각 하나가 통과한 뒤에 다음으로 간다. `start` 절차의 마무리로 간다.

**보고:** 바뀐 구조, 기준으로 삼은 고정 장치, 동등성 증명, 읽는 부담의 변화, 낸 것과 되돌린 것. 새 동작은 없다.
