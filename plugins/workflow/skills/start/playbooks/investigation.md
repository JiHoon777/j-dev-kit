# Investigation

> 원문: `cursor/plugins`의 `pstack/skills/poteto-mode/playbooks/investigation.md` (MIT, Lauren Tan). Cursor 이름을 Claude Code 것으로 바꾸고 가져오지 않은 스킬을 가리키는 줄을 뺐다.

**언제:** 코드는 고치지 않고 알아보기만 하는 요청. "이게 어떻게 동작해?", "왜 이렇게 되지?", "둘 중 뭐가 낫지?", "코드는 아직 고치지 마".

**답의 주인은 나다. 계획하고, 길을 잡고, 쓴다.**

조사 요청은 읽기만 한다. 결과물은 근거를 단 설명이나 추천이지 코드 변경이 아니다.

1. 질문이 가리키는 코드를 추적한다. 왜 그렇게 됐는지를 묻는 질문이면 `why` 스킬도 거친다.
2. 처리량 점검은 한 줄로 둔다: `처리량 점검: 해당 없음, 읽기만 하는 조사`.
3. 결과물을 쓴다(개요 / 핵심 개념 / 어떻게 동작하나 / 무엇이 어디에 있나 / 함정). 여러 안 가운데 고르는 요청이면 맞바꾸는 것을 표로 붙인 추천을 쓴다.
4. 답에 `unslop` 스킬을 적용한다.

항목 없이 한 조사는 브랜치를 따지 않고 커밋·리뷰·머지를 하지 않는다. 백로그 항목이 조사이면 결과를 항목 파일에 적고 여느 항목처럼 닫는다(`start` 절차 3단계 3의 "조사와 시제품"). `architect`는 쓰지 않는다. 조사가 코드 변경으로 이어져야 하면 스스로 고치지 않고 사용자에게 돌려준다. 항목 없이 한 조사면 답에 그렇다고 적고, 백로그 항목이면 `start` 절차 10단계 메시지에 "나중" 후보로 올린다. 고치는 일은 `bug-fix.md`나 `feature.md`로 다시 잡는다.

**보고:** 조사 결과. "확실한가?"에 답할 때는 실제 판단과 이유를 적는다. 전제가 틀렸으면 그렇다고 말한다(`start` 스킬의 "아니라고 말해도 된다").
