# ui mockup: 시안 만들고 고르고 기록하기

한 번에 화면 하나만 다룬다.

## 1. 브리프

화면, 쓰는 사람, 그 화면에서 할 일, 실제 문구와 데이터를 정한다. 코드와 문서로 알 수 없는 것만 묻고, 질문은 한 번에 최대 3개다. **시안 수는 꼭 묻는다.**

- **1개:** 방향 하나로 바로 만든다. 2단계는 건너뛴다.
- **여러 개:** 기본 3개, 최대 5개. 만든 뒤 비교해서 고른다.

DESIGN.md 가 없으면 `/ui system`을 먼저 권한다. 사용자가 그냥 진행하자고 하면 진행한다.

## 2. 방향 (여러 개일 때만)

만들기 전에 표로 보여 주고 확인받는다.

| 이름 | 축 | 좋은 점 | 대가 |
| --- | --- | --- | --- |

- 이름은 내용을 말한다("Option A" 금지).
- 축은 위계, 레이아웃, 타이포, 색, 밀도, 구성 중 하나다. 방향마다 다른 축을 쓴다.
- 두 시안의 헤드라인을 서로 바꿔도 티가 안 나면 너무 비슷하다. 하나를 바꾼다.
- 색과 글꼴은 DESIGN.md 를 따른다. 정체성까지 바꾸는 방향은 사용자가 원할 때만 넣는다.

## 3. 캔버스

Artifact 도구로 Design 캔버스를 만든다(`action: quickstart`, `intent: design`, `design_systems: false`). 디자인 시스템은 이 레포의 DESIGN.md 로 지정한다. 아트보드는 방향당 하나이고, 제목은 방향 이름이다. 실제 문구를 쓰고 lorem ipsum 은 쓰지 않는다.

만들고 나면 링크를 주고 **멈춘다.** 사용자가 캔버스에서 보고, 직접 고치고, 고른다. 미리 추천하지 않는다.

## 4. 다듬기

고른 뒤에는 그 아트보드만 고친다. 사용자가 다시 넓혀 보자고 하기 전에는 새 방향을 만들지 않는다.

## 5. 기록

사용자가 "됐다"고 하면 기록한다.

1. 폴더는 `docs/design/<NNN>-<slug>/`다. NNN 은 `docs/design/`의 마지막 번호 + 1 이고, 처음이면 001 이다.
2. 캔버스를 다시 읽어 사용자 편집까지 그 폴더로 받는다(`action: read`, `url`, `paths`, `out_dir`).
3. `decisions.md`를 쓴다.

   ```markdown
   # <화면>

   - 날짜: <오늘>
   - 캔버스: <링크>
   - 브리프: <한 문장>
   - 고른 안: <이름> — <이유>
   - 버린 안: <이름> — <이유> (시안이 1개면 뺀다)
   - 다듬으며 바꾼 것: …
   - 남은 질문: …
   ```

4. 승인받고 `design(<NNN>): <화면> 시안`으로 커밋한다.

## 캔버스를 못 쓸 때

Artifact 도구가 없거나 거부되면(API 키 로그인, `claude -p`, 조직 설정) 같은 폴더에 `variants.html` 하나를 쓴다. 이 파일은 시안을 탭으로 바꿔 보는 단일 HTML 이다. 브라우저로 열어 보여 주고, 3단계부터 같은 절차를 따른다. `decisions.md`의 캔버스 줄에는 `variants.html`을 적는다.
