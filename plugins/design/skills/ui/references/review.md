# ui review: 구현된 화면 리뷰

## 1. 준비

- **화면:** 인자로 받은 URL 을 쓴다. 없으면 개발 서버를 띄운다(`.claude/launch.json`이 있으면 그것). 작업 브랜치 항목의 `### 포트`에 웹 포트가 있으면 `.claude/launch.json`의 포트보다 그것을 쓴다. 개발 명령이 포트를 받는 방식(예: Vite `--port`, 위치 인자, `PORT` 환경 변수)을 스크립트에서 확인해 그 포트로 띄우고, 실제로 그 포트에서 듣는지(`lsof -nP -iTCP:<포트> -sTCP:LISTEN`) 확인한 뒤 화면 URL 에 쓴다. 백엔드 서버도 띄워야 하면 같은 방식으로 서버 포트에 띄운다. 어느 화면인지 모르면 묻는다.
- **기준:** 루트 `DESIGN.md`와, 이 화면의 `docs/design/*/decisions.md`. 맞는 기록이 여럿이거나 분명하지 않으면 묻는다. 둘 다 없으면 접근성과 일관성만 본다고 말한다.

## 2. 리뷰

`design:design-reviewer` 에이전트를 띄운다. 넘기는 것은 URL, DESIGN.md 경로, decisions.md 경로, 볼 코드 경로다.
