# arch review: 기존 코드베이스 리뷰

기존 코드베이스(또는 경로 하나)를 `references/criteria.md`의 기준으로 리뷰한다. **코드는 고치지 않는다.** 사용자가 고른 지적만 문서(ADR, 개요 문서의 알려진 부채)에 적는다.

범위: `review` 뒤의 경로(`--research` 뺌). 없으면 저장소 전체.

## 1. 시작할 수 있는지

- git 저장소가 아니면 측정 중 git 부분을 건너뛰고 그렇다고 적는다.
- 범위에 코드가 거의 없으면(파일 몇 개) 리뷰할 구조가 없다고 말하고 `/arch design`을 권한다.

## 2. 시스템 지도

1. 읽는다: 개요 문서와 ADR(`references/docs.md`의 위치), CLAUDE.md, 매니페스트, 최상위·두 번째 단계 폴더, 진입점.
2. 짧게 그린다:
   - 앱 종류와 스택(버전 포함)
   - 모듈 목록: 경로 → 책임 → 공개 인터페이스 → 무엇 때문에 바뀌나
   - 의존 방향
   - 품질 목표: 문서에 있으면 그것을, 없으면 추론해 "추론"이라고 표시
3. 보여 주고 묻는다: "이 지도가 맞나요? 틀린 곳이나 리뷰에서 특히 볼 곳이 있으면 말씀해 주세요." 틀린 지도 위에서 판단하지 않는다. 사용자가 고친 것을 반영한다.

## 3. 측정

읽기 전용 명령만 돌린다. 빌드, 테스트, 설치, 서버 실행은 하지 않는다. 범위가 경로 하나면 명령에 `-- <경로>`를 붙인다. 생성된 파일, 의존성 폴더, 잠금 파일은 뺀다. 명령은 bash 기준이다. 실패하면 그 측정을 "측정 못 함"으로 적고 넘어간다.

```bash
# 큰 파일 상위 20개 (줄 수)
git ls-files | grep -vE '(^|/)(vendor|node_modules|dist|build|generated|__generated__)/|\.(lock|svg|png|jpg|jpeg|gif|ico|pdf|min\.js|map)$|(^|/)[^/]*lock[^/]*$' \
  | tr '\n' '\0' | xargs -0 wc -l 2>/dev/null | grep -v ' total$' | sort -rn | head -20

# 핫스팟: 최근 12개월 변경 횟수와 줄 수
git log --since='12 months ago' --no-merges --name-only --format= | grep -v '^$' | sort | uniq -c | sort -rn | head -40 \
  | while read -r n f; do [ -f "$f" ] && printf '%s\t%s\t%s\n' "$n" "$(wc -l < "$f")" "$f"; done | head -20

# 커밋당 바뀐 파일 수 (중앙값, 상위 10%)
git log --since='12 months ago' --no-merges --name-only --format='@@%h' \
  | awk '/^@@/{if(n)print n; n=0; next} NF{n++} END{if(n)print n}' | sort -n \
  | awk '{a[NR]=$1} END{if(!NR) exit; p=int(NR*0.9); if(p<1)p=1; print "commits", NR, "median", a[int((NR+1)/2)], "p90", a[p]}'

# 함께 바뀌는 파일 쌍 (3번 이상, 20개 넘게 바뀐 커밋은 뺌)
git log --since='12 months ago' --no-merges --name-only --format='@@%h' | awk '
  function flush(  i,j,a,b,t){ if(k>1 && k<=20) for(i=1;i<=k;i++) for(j=i+1;j<=k;j++){ a=f[i]; b=f[j]; if(a>b){t=a;a=b;b=t} c[a" "b]++ } k=0 }
  /^@@/{flush(); next} NF{f[++k]=$0} END{flush(); for(p in c) if(c[p]>=3) print c[p], p}' | sort -rn | head -20
```

그리고 본다:

- **검증 명령:** CLAUDE.md, `package.json` scripts, `Makefile`, `justfile`, CI 설정에 린트·타입·테스트가 있는가. 돌리지는 않는다.
- **아키텍처 검사 도구:** `references/enforce.md` 표의 도구 설정 파일이 있는가.
- **지원 종료:** 주 언어·런타임·프레임워크의 지금 버전이 지원 중인가. `architecture-researcher`를 띄워 [endoflife.date](https://endoflife.date/) 로 확인한다. 이것만 하는 짧은 조사다.

측정 결과에서 **핫스팟 상위**와 **함께 바뀌는 먼 파일 쌍**을 리뷰 범위의 우선순위로 쓴다. 자주 바뀌지 않는 오래된 코드는 비용이 보이지 않으면 깊게 보지 않는다.

## 4. 리서치 (`--research`일 때만)

`references/research.md`대로 `architecture-researcher`를 띄워 이 앱 종류와 스택의 최신 구조 지침을 조사한다. 3절의 지원 종료 확인과 한 메시지에서 동시에 띄운다. 결과에서 `references/criteria.md`와 다르거나 더할 것을 표시한다.

## 5. 리뷰

`architecture-reviewer` 에이전트를 띄운다.

- 모듈이 다섯 개 이하이거나 범위가 작으면 1개.
- 크면 2절의 모듈 지도를 영역 2~3개로 나눠 한 메시지에서 동시에. 영역을 가로지르는 의존은 각 에이전트에게 "경계 너머로 무엇을 쓰는지"를 보게 해 합칠 때 본다.

에이전트는 이 대화를 볼 수 없으니 지시문에 넣는다:

1. 기준 파일의 절대 경로: `<이 스킬의 폴더>/references/criteria.md`
2. 맡은 범위(경로)와 2절의 시스템 지도(사용자가 고친 것 반영), 품질 목표
3. 3절의 측정 결과(그 범위에 해당하는 것)와 지원 종료 결과, 4절의 리서치 요약(있으면)
4. 개요 문서와 ADR 경로
5. 읽기만 한다: 파일을 고치지 않고, 빌드·테스트·설치·서버 명령을 돌리지 않는다.

## 6. 보여 주고 묻기

모두 돌아온 뒤:

1. 중복을 합친다.
2. 지적마다 직접 코드를 열어 확인한다. 틀린 지적, 증거 없는 지적, `criteria.md`의 "지적하지 말 것"에 해당하는 지적은 뺀다.
3. 나눈다:
   - 🔴 꼭 고칠 것: 이미 비용이 나고 있는 구조 문제(핫스팟이거나 변경마다 여러 모듈을 건드리게 함), 순환 의존, 품질 목표 1순위를 막는 것, 지원이 끝난 런타임·프레임워크
   - 🟡 고려: 실제 문제지만 지금 비용은 작음
   - ⚪ 사소함: 개수만

```markdown
### 시스템 지도 (확인됨)
<짧게>

### 측정
- 커밋당 파일 수: 중앙값 N, 상위 10% N
- 핫스팟 상위 5: …
- 함께 바뀌는 먼 파일 쌍: …
- 검증 명령: … / 아키텍처 검사: 있음(도구) / 없음
- 지원 종료: …

🔴 꼭 고칠 것
- `src/a.ts:12` — 문제 — 기준: 2 결합도·응집도 (출처) — 고칠 방향 — 고치면 쉬워지는 것

🟡 고려
- …

⚪ 사소함 N건 (보려면 말씀해 주세요)

### 검사로 막을 수 있는 것
- <규칙> — <도구> (`references/enforce.md` 4절 형식)

### 확인 못 함
- …
```

묻는 것은 한 번: "지적마다 **ADR 로 결정** / **알려진 부채로 기록** / **그대로** 중에 정해 주세요. 🔴 는 ADR 이나 부채 기록을 권합니다." 사용자가 원하면 하나씩 정한다. 답을 받기 전에는 아무것도 쓰지 않는다.

## 7. 문서 쓰기

- **ADR 로 결정:** 고칠 방향에 대안이 있으면 `references/docs.md` 3절 형식으로 `proposed` ADR 을 쓴다. 사용자가 방향까지 정했으면 `accepted`. 리서치를 했으면 리서치 파일도 저장하고 링크한다.
- **알려진 부채로 기록:** 개요 문서의 "알려진 부채"에 한 줄씩. 개요 문서가 없으면 2절의 시스템 지도로 개요 문서를 만들지 묻는다.
- **그대로:** 아무것도 쓰지 않는다.
- 코드는 고치지 않는다. 고치는 작업은 사용자가 따로 한다(예: 백로그 항목으로).

보고: 쓴 파일, 지적별로 정한 것, 확인 못 한 것. 커밋은 사용자가 요청할 때만.
